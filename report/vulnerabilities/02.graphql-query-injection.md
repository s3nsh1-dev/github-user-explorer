## What is wrong

Three hooks build GraphQL documents by **string-interpolating a value that
comes straight from the URL path**, with no escaping and no use of GraphQL
variables:

```ts
// client/src/hooks/useFetchLoginType.ts:6-10
const queryBodyToFetchLoginType = `
  {
    repositoryOwner(login: "${username}") {
      __typename
    }
  }`;
```

`username` originates from `useParams()` on the route `/user/:username`
([`client/src/App.tsx:22`](../../client/src/App.tsx#L22)). React Router
**percent-decodes** path params before handing them to you, so a `%22` in the
address bar arrives as a literal `"` — which closes the string literal in the
GraphQL document.

Same pattern in:

- [`useFetchContributionInfo.ts:8`](../../client/src/hooks/useFetchContributionInfo.ts#L8) — `user(login: "${username}")`
- [`useFetchOrganizationRepos.ts:8`](../../client/src/hooks/useFetchOrganizationRepos.ts#L8) — `organization(login: "${username}")`

## Proof of concept

Visit:

```
/user/a%22)%20%7B__typename%7D%20viewer%20%7Blogin%20email%7D%20z%3A%20repositoryOwner(login%3A%22b
```

The param decodes to:

```
a") {__typename} viewer {login email} z: repositoryOwner(login:"b
```

…and the document actually sent to `api.github.com/graphql` becomes:

```graphql
{
  repositoryOwner(login: "a") {__typename} viewer {login email} z: repositoryOwner(login:"b") {
    __typename
  }
}
```

That is syntactically valid. `viewer` resolves to **the token owner** — you —
and returns your login and email. The same technique reaches anything the
token's scopes allow, e.g.:

```graphql
viewer { repositories(first: 100, privacy: PRIVATE) { nodes { nameWithOwner } } }
```

An attacker does not even need a victim to click the link — with the token
already public (see [01](01.exposed-github-token.md)) they can run the query
directly. **That is exactly why this must be fixed together with 01:** the
moment the token moves server-side and becomes secret again, this injection is
the remaining hole that hands an anonymous visitor arbitrary use of it.

### Secondary impact: denial of service on your own quota

GitHub's GraphQL API bills by computed node cost. An injected

```graphql
z: search(query:"a", type:USER, first:100) { nodes { ... on User { followers(first:100) { nodes { login } } } } }
```

burns a large share of the 5,000-point/hour budget in one request.

### Tertiary impact: broken app for legitimate names

Even without malice, this breaks on ordinary input. A username containing `"`
or `\` produces a malformed document; GitHub returns HTTP 200 with an `errors`
array and `"data": null`, which then crashes the renderer — see
[05.unhandled-api-errors.md](05.unhandled-api-errors.md).

## How to fix

Use GraphQL **variables**. The value is then transported out-of-band and can
never be parsed as query syntax:

```ts
const QUERY = /* GraphQL */ `
  query LoginType($login: String!) {
    repositoryOwner(login: $login) {
      __typename
    }
  }
`;

const response = await fetch("https://api.github.com/graphql", {
  method: "POST",
  headers: { "Content-Type": "application/json", Authorization: `Bearer ${TOKEN}` },
  body: JSON.stringify({ query: QUERY, variables: { login: username } }),
});
```

Add a cheap validation gate as defence in depth, since GitHub usernames have a
strict grammar (alphanumeric + single hyphens, ≤ 39 chars):

```ts
// client/src/helper/validateLogin.ts
export const GITHUB_LOGIN = /^[a-zA-Z0-9](?:[a-zA-Z0-9]|-(?=[a-zA-Z0-9])){0,38}$/;
export const isValidLogin = (v: string) => GITHUB_LOGIN.test(v);
```

Reject at the route boundary and render `NotFound` for anything that fails —
this also cleans up [03](03.api-url-tampering.md) and gives the app a real
404 path instead of an API error string.

If a proxy is introduced ([../suggestions/01.backend-api-proxy.md](../suggestions/01.backend-api-proxy.md)),
**the query documents must live on the server** and the client must send only
`{ login }`. A proxy that forwards a client-supplied `query` string is exactly
as vulnerable as this code, with a secret token behind it.

## Contradictions & trade-offs

- **Ordering conflict with [01](01.exposed-github-token.md).** Fixing 01 alone
  *raises* this issue's severity. Ship both together.
- **The strict-validation gate conflicts with the current
  "always render something" behaviour.** Today `ProfileInfo` falls back to
  `username || "demoUserName"` ([`ProfileInfo.tsx:46`](../../client/src/page/ProfileInfo.tsx#L46));
  a validation gate replaces that with a hard 404. That is the better UX but it
  changes visible behaviour — pair it with
  [../suggestions/10.empty-and-notfound-states.md](../suggestions/10.empty-and-notfound-states.md)
  so the 404 page is worth landing on.
- **GraphQL variables change the response-shape assumptions slightly** (aliases
  disappear). The type definitions in
  [`common.types.ts:136-160`](../../client/src/constants/common.types.ts#L136)
  stay valid, but any hand-written alias would not.
