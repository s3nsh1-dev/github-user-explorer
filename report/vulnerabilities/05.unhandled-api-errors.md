# 05 · Unhandled API Error Shapes Crash the Whole App (No Error Boundary)

| Field | Value |
|---|---|
| **Severity** | 🟡 Medium (availability) |
| **Category** | Improper error handling (CWE-248) / missing fail-safe |
| **Exploitable by** | Anyone; also triggered accidentally by normal use |
| **Status** | Open |

---

## What is wrong

There is **no `<ErrorBoundary>` anywhere in the tree**
([`main.tsx`](../../client/src/main.tsx),
[`App.tsx`](../../client/src/App.tsx)). In React 19, an uncaught render error
unmounts the entire root — the visitor gets a blank white page, not a degraded
component. Several code paths reach that state on inputs a visitor can produce.

### 5a. GraphQL errors return HTTP 200 — the `!ok` check never fires

```ts
// client/src/hooks/useFetchLoginType.ts:24-26
if (!response.ok) throw new Error("Response for LongType was not ok");
const responseData = await response.json();
```

GraphQL signals failure **in the body**, with status 200:

```json
{ "data": null, "errors": [{ "message": "Could not resolve to a User with the login of 'xyz'." }] }
```

`response.ok` is `true`, so the hook resolves successfully with `data: null`.
Then:

```ts
// client/src/components/ContributionChart.tsx:8
const loginType: string = data.data.repositoryOwner?.__typename.toLowerCase();
```

`data.data` is `null` → reading `.repositoryOwner` throws `TypeError`. The
optional chain on `repositoryOwner?.` does not help; the crash is one property
earlier.

**Trigger:** visit `/user/` + any non-existent GitHub login, e.g.
`/user/zzzz-not-a-real-user-zzzz`. Also triggered by an expired or revoked
token (`{"message": "Bad credentials"}` at HTTP 401 → caught) *or* a
rate-limited GraphQL response (HTTP 200 + `errors` → **not** caught).

### 5b. Same shape, deeper access

```ts
// client/src/components/UserContributions.tsx:28-32
const totalContributions = data.data.user.contributionsCollection.contributionCalendar.totalContributions;
const weeks = data.data.user.contributionsCollection.contributionCalendar.weeks;
```

Four unguarded hops. Any GraphQL error, or querying an *organization* login
(where `user` is `null`), throws.

### 5c. Wrong fallback when the type is unknown

```ts
// ContributionChart.tsx:10-14
return loginType === "user" ? <UserContributions/> : <OrganizationTopRepos/>;
```

If `loginType` is `undefined` (error, or a login that is neither), the code
renders the **organization** view — which then fetches org repos for a
non-organization and shows "🚫 No repositories found for this organization" for
a user. Misleading rather than crashing, but wrong.

### 5d. `JSON.parse` on attacker-writable storage

```ts
// client/src/context/StaredUserContextProvider.tsx:9-11
const initialList: string[] = JSON.parse(
  window.localStorage.getItem("staredProfiles") || "[]"
);
```

No `try`/`catch`. Any malformed value throws **during render**, on the very
first paint of `Home`. A visitor can reach this by:

- running `localStorage.setItem('staredProfiles','{')` in their own console
  (self-inflicted, but the app is then permanently bricked for that browser
  with no way back except clearing storage), or
- an extension or a previous buggy build writing a bad value.

Worse: if the parse *succeeds* but returns a non-array (`localStorage.setItem('staredProfiles','5')`),
`staredList.map` at [`StaredRepositories.tsx:71`](../../client/src/components/StaredRepositories.tsx#L71)
throws instead.

Same untrusted-read pattern, unvalidated, at
[`ModeContextProvider.tsx:6`](../../client/src/context/ModeContextProvider.tsx#L6):

```ts
const localStorageValue = localStorage.getItem("mode") as ModeType;
```

The `as ModeType` is a lie to the compiler — the value could be anything.

## How to fix

**1. Add an error boundary at the root** (react-error-boundary, ~1 kB, or a
15-line class component):

```tsx
// client/src/components/AppErrorBoundary.tsx
class AppErrorBoundary extends React.Component<{children: React.ReactNode}, {error: Error | null}> {
  state = { error: null as Error | null };
  static getDerivedStateFromError(error: Error) { return { error }; }
  render() {
    if (this.state.error) return <SomethingWentWrong onRetry={() => this.setState({ error: null })} />;
    return this.props.children;
  }
}
```

Wrap `<App />` in [`main.tsx`](../../client/src/main.tsx), and wrap
`<ContributionChart>` separately so a broken contribution graph does not take
down the profile page around it.

**2. Surface GraphQL errors as real errors** in every GraphQL hook:

```ts
const json = await response.json();
if (json.errors?.length) throw new Error(json.errors[0].message);
if (!json.data) throw new Error("Empty GraphQL response");
return json.data;   // return `data`, not the envelope
```

Returning `json.data` also flattens the awkward `data.data.user…` access in the
components.

**3. Guard the storage reads:**

```ts
const readStarred = (): string[] => {
  try {
    const parsed = JSON.parse(localStorage.getItem("staredProfiles") ?? "[]");
    return Array.isArray(parsed) ? parsed.filter((v): v is string => typeof v === "string") : [];
  } catch { return []; }
};

const readMode = (): ModeType => {
  const v = localStorage.getItem("mode");
  return v === "dark" || v === "light" ? v : "light";
};
```

**4. Configure a QueryClient default** so failures are consistent rather than
per-hook:

```ts
// main.tsx:9
const queryClient = new QueryClient({
  defaultOptions: { queries: { retry: 1, staleTime: 5 * 60_000, refetchOnWindowFocus: false } },
});
```

(`guide.txt` lists "Handle auth and errors globally using React Query's
QueryClient config" as a planned task — this is it, still unstarted.)

## Contradictions & trade-offs

- **Returning `json.data` instead of the envelope is a breaking change to three
  consumers.** `ContributionChart`, `UserContributions`, and
  `OrganizationTopRepos` all read `data.data.…`, and the types
  `ContributionCalendarResponse` / `OrganizationTop10ReposType`
  ([`common.types.ts:115-160`](../../client/src/constants/common.types.ts#L115))
  model the envelope. Change hooks, components, and types in one commit or the
  build breaks midway.
- **Fixing 5a/5b interacts with
  [02.graphql-query-injection.md](02.graphql-query-injection.md).** The
  injection fix makes malformed-document errors far rarer, which can mask this
  bug in testing. Test 5a explicitly with a known-bad username, not by trying
  to break the query.
- **An error boundary can hide bugs during development.** Keep it out of the
  path in dev (or log to console in `componentDidCatch`), otherwise crashes
  become silent "Something went wrong" cards.
- **`retry: 1` conflicts with rate limiting.** On HTTP 403 (rate limit
  exceeded) retrying is actively harmful — add
  `retry: (count, err) => count < 1 && !isRateLimit(err)`. See
  [07.rate-limit-exhaustion.md](07.rate-limit-exhaustion.md).
