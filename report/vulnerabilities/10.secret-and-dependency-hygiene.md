## What is already correct — verified

Worth stating, because it is the part most portfolio projects get wrong:

- **No secret has ever been committed.** Searched the full history:
  ```bash
  git log --all -p -S"ghp_"        # no results
  git log --all -p -S"github_pat"  # no results
  git log --all --name-only --pretty=format: | grep -i env   # only vite-env.d.ts
  ```
  No `.env` file appears in any commit or any branch.
- **[`.gitignore`](../../.gitignore) is thorough** and covers `.env`, `.env.*`,
  `client/.env*`, `server/.env*`, `dist/`, `build/`, and editor junk. Good.
- **No `dangerouslySetInnerHTML`, no `eval`, no `innerHTML`** anywhere in
  `client/src`. All user- and API-supplied strings go through JSX text nodes,
  so React's escaping handles them. **The app has no XSS sink.** That is a real
  strength and worth saying out loud in the README.

The token exposure in [01.exposed-github-token.md](01.exposed-github-token.md)
is an *architecture* problem, not a leaked-file problem. `.gitignore` did its
job; the build system exported the secret anyway.

## Gaps

### 10a. No `.env.example`

Nothing in the repo documents that `VITE_GITHUB_AUTHENTICATION_TOKEN` is
required. A visitor who clones this cannot run it, and
[`vite-env.d.ts`](../../client/src/vite-env.d.ts) does not declare it either
(it holds only the default `/// <reference types="vite/client" />`). Add:

```bash
# .env.example — committed; real values never are
VITE_GITHUB_AUTHENTICATION_TOKEN=   # (to be removed once the proxy lands — see suggestions/01)
```

…and type it so misspellings fail the build:

```ts
// client/src/vite-env.d.ts
/// <reference types="vite/client" />
interface ImportMetaEnv { readonly VITE_GITHUB_AUTHENTICATION_TOKEN: string }
interface ImportMeta { readonly env: ImportMetaEnv }
```

### 10b. A stray root `package.json` / `package-lock.json`

```json
// package.json (repo root)
{ "dependencies": {} }
```

…yet [`package-lock.json`](../../package-lock.json) at the root pins
`react-router-dom@7.6.2`, `react@19.1.0`, `cookie@1.0.2`, and friends. The lock
file and the manifest disagree: the lock records a `react-router-dom`
dependency the manifest no longer declares. This is the residue of an
`npm install` run in the wrong directory.

Consequences: `npm audit` at the root audits a phantom tree; a reviewer running
`npm install` at the root installs packages that are never used; and the real
dependency set in `client/` gets skipped. Either delete both root files, or
make the root a proper workspace:

```json
{
  "name": "github-user-explorer",
  "private": true,
  "workspaces": ["client", "server"],
  "scripts": {
    "dev": "npm run dev -w client",
    "build": "npm run build -w client",
    "lint": "npm run lint -w client"
  }
}
```

The workspace form is better here — the repo is already structured as
client + server, and it gives one `npm install` at the root.

### 10c. `server/` is an empty stub

[`server/package.json`](../../server/package.json) declares
`"main": "index.js"` with no `index.js`, no dependencies, and a `test` script
that exits 1. It signals a backend that does not exist. Either implement it
(it is the fix for [01](01.exposed-github-token.md) — see
[../suggestions/01.backend-api-proxy.md](../suggestions/01.backend-api-proxy.md))
or delete the folder. Leaving a dead stub in a portfolio repo reads as
abandoned scaffolding.

### 10d. No automated dependency auditing

No `npm audit` in CI, no Dependabot config, no `.github/` directory at all.
`client/package-lock.json` is ~4,000 lines of transitive packages that will
drift. Minimum viable setup:

```yaml
# .github/dependabot.yml
version: 2
updates:
  - package-ecosystem: npm
    directory: /client
    schedule: { interval: weekly }
    open-pull-requests-limit: 5
```

Plus `npm audit --audit-level=high` as a CI step — see
[../suggestions/11.testing-and-ci.md](../suggestions/11.testing-and-ci.md).

## Contradictions & trade-offs

- **`.env.example` documenting `VITE_GITHUB_AUTHENTICATION_TOKEN` contradicts
  [01](01.exposed-github-token.md)**, which says that variable should stop
  existing. Add the file now with the deprecation comment, and delete the entry
  when the proxy lands — do not let the example file outlive the variable.
- **Converting the root to npm workspaces changes every deploy command.** A
  Vercel project configured with root directory `client` and `npm run build`
  keeps working; one configured at the repo root does not. Update host settings
  in the same change.
- **Deleting `server/` conflicts with the recommended fix for
  [01](01.exposed-github-token.md).** Decide the architecture first
  (proxy vs. token-free), then clean up — not the other way round.
- **Dependabot PRs on a portfolio repo add noise to your commit graph.**
  Some people like the activity; others find weekly bump PRs clutter the
  history a reviewer reads. `interval: monthly` is a reasonable compromise.
