| `connect-src` | ✅ `'self'`, **not** `api.github.com` — the doc's condition ("change this if you build the proxy") was met before the header shipped |

Verified: **zero CSP violations across eight pages**, with avatars decoding,
Roboto loading and Emotion's runtime styles intact.

| Anti-flash theme script | 🚫 **built, then deliberately removed** — see below |

**Outstanding: none here.** One related follow-up lives in another finding:
self-hosting Roboto would let both font exceptions be dropped
([suggestions/07](../suggestions/07.asset-and-bundle-weight.md)).

### 🚫 The anti-flash script was reverted, on purpose

It shipped briefly after S7 and was removed in the simplification pass. It
worked — but making it work under `script-src 'self'` meant an inline script
pinned by a `'sha256-…'`, plus an `npm run csp-hash` tool whose only job was to
notice when a one-character edit had silently invalidated that hash.

Three coupled moving parts, one of them failing silently, to remove a brief
flash on first load. **On a portfolio project that is a bad trade** — the CSP
is worth having as one line of config, and it stops being worth having the
moment it needs its own tooling.

`script-src` is plain `'self'` again. If the flash ever matters, the cheap
version is a `<body>` background in CSS that matches `prefers-color-scheme` —
no script, no hash, no tool.

## Before → After

**Before** — no host configuration existed anywhere in the repo. No
`netlify.toml`, no `_headers`, no `_redirects`. The deployed site sent browser
defaults and nothing else, and whatever redirect rule existed lived only in the
Netlify dashboard — unversioned and undocumented.

**After** — one `netlify.toml` at the root, carrying four concerns:

```toml
[[redirects]]                      # 1. the proxy
  from = "/api/*"
  to   = "/.netlify/functions/:splat"
  status = 200
  force  = true

[[redirects]]                      # 2. SPA fallback — MUST stay below /api/*
  from = "/*"
  to   = "/index.html"
  status = 200

[[headers]]                        # 3. security headers
  for = "/*"
  [headers.values]
    Content-Security-Policy = "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com; img-src 'self' data: https://*.githubusercontent.com; connect-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'none'; object-src 'none'"
    X-Content-Type-Options  = "nosniff"
    Referrer-Policy         = "strict-origin-when-cross-origin"
    Permissions-Policy      = "camera=(), microphone=(), geolocation=()"

[[headers]]                        # 4. caching
  for = "/assets/*"
  [headers.values]
    Cache-Control = "public, max-age=31536000, immutable"
```

### Previous vs current

| | Before | After |
|---|---|---|
| CSP | none | `script-src 'self'`, no `unsafe-inline` |
| Clickjacking | framable by anyone | `frame-ancestors 'none'` |
| Deep-link refresh | **404** — verified on the live site | 200, via the SPA fallback |
| Asset caching | host default | 1 year immutable; `index.html` never cached |
| Where config lived | a dashboard | the repo |

### Two directives that would break the site if "tightened"

- **`style-src 'unsafe-inline'` is mandatory.** Emotion — MUI's styling engine —
  injects every rule at runtime. Removing it blanks the entire UI. Inline
  *styles* are not the risk inline *scripts* are, and `script-src 'self'` with
  no `unsafe-inline` is the directive doing the real work.
- **`connect-src 'self'`** is only correct *because* the proxy landed first. On
  the pre-proxy client, which called `api.github.com` directly, it would have
  broken every request. P35 shipping after P34 was not a preference.

### The one thing deliberately not done

The anti-flash inline theme script was reverted. It needed either a SHA-256
hash in `script-src` or `'unsafe-inline'`, and a brief white flash on first
paint is a far smaller problem than weakening the one directive that matters.

## What is wrong

The repository contains **no host configuration file at all** — no
`vercel.json`, `netlify.toml`, `public/_headers`, `nginx.conf`, or
`staticwebapp.config.json`. The deployed site therefore serves whatever
defaults the host provides, which for every major static host means:

| Header | Current | Consequence |
|---|---|---|
| `Content-Security-Policy` | absent | No mitigation if any script on the page is ever compromised; no restriction on where data can be exfiltrated to |
| `X-Frame-Options` / CSP `frame-ancestors` | absent | The site can be iframed by any origin → clickjacking |
| `Referrer-Policy` | absent (browser default `strict-origin-when-cross-origin`) | Acceptable, but not pinned |
| `X-Content-Type-Options` | absent | MIME sniffing on served assets |
| `Permissions-Policy` | absent | Camera/mic/geolocation not explicitly denied |

There is also no `index.html` `<meta http-equiv="Content-Security-Policy">`
fallback ([`client/index.html`](../../client/index.html)).

## Why it matters here specifically

This is a public portfolio site, so the realistic threat is not a targeted
attack — it is **blast radius**. The app pulls a full MUI + Emotion dependency
tree (`client/package-lock.json` is ~4,000 lines of transitive packages). A
single compromised transitive dependency in a future `npm install` gets
arbitrary JS execution on your origin with:

- no CSP to stop it beaconing data to an attacker-controlled host, and
- (today) **a live GitHub PAT sitting in the same bundle** — see
  [01.exposed-github-token.md](01.exposed-github-token.md).

Emotion (MUI's styling engine) injects styles at runtime, so a naive
`style-src 'self'` will break the entire UI. That constraint shapes the policy
below.

## How to fix

### If deploying on Vercel

```json
// vercel.json  (repo root)
{
  "headers": [
    {
      "source": "/(.*)",
      "headers": [
        {
          "key": "Content-Security-Policy",
          "value": "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com; img-src 'self' data: https://avatars.githubusercontent.com https://*.githubusercontent.com; connect-src 'self' https://api.github.com; frame-ancestors 'none'; base-uri 'self'; form-action 'none'; object-src 'none'"
        },
        { "key": "X-Content-Type-Options", "value": "nosniff" },
        { "key": "Referrer-Policy", "value": "strict-origin-when-cross-origin" },
        { "key": "Permissions-Policy", "value": "camera=(), microphone=(), geolocation=(), interest-cohort=()" }
      ]
    }
  ],
  "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
}
```

### If deploying on Netlify

```
# client/public/_headers
/*
  Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com; img-src 'self' data: https://*.githubusercontent.com; connect-src 'self' https://api.github.com; frame-ancestors 'none'; base-uri 'self'; object-src 'none'
  X-Content-Type-Options: nosniff
  Referrer-Policy: strict-origin-when-cross-origin
  Permissions-Policy: camera=(), microphone=(), geolocation=()
```

```
# client/public/_redirects
/*  /index.html  200
```

### Policy notes

- `'unsafe-inline'` in `style-src` is **required** by Emotion/MUI. It is a real
  weakening, but style-only injection is a far smaller risk than script
  injection, and `script-src 'self'` (no `'unsafe-inline'`) is the line that
  actually matters.
- `img-src` must allow `*.githubusercontent.com` — avatars come from there
  ([`UserCards.tsx:31`](../../client/src/components/UserCards.tsx#L31),
  [`UserProfileHeader.tsx:42`](../../client/src/components/UserProfileHeader.tsx#L42)).
- `connect-src https://api.github.com` is only correct while the client calls
  GitHub directly. **If you build the proxy
  ([../suggestions/01.backend-api-proxy.md](../suggestions/01.backend-api-proxy.md)),
  change this to your API origin and drop `api.github.com`** — otherwise you
  leave open the exact channel a fix was meant to close.
- Verify afterwards at <https://securityheaders.com> or with
  `curl -I https://<your-site>`.

## Contradictions & trade-offs

- **The rewrite rule is not optional and is separate from CSP.** Without
  `/* → /index.html`, deep links like `/user/torvalds` return a hard 404 on
  every static host. See
  [../suggestions/13.deployment-config.md](../suggestions/13.deployment-config.md).
- **A strict CSP will break the Google Fonts `<link>` in
  [`index.html:11-15`](../../client/index.html#L11)** unless
  `fonts.googleapis.com` / `fonts.gstatic.com` are allowed, as above. Self-hosting
  Roboto via `@fontsource/roboto` removes both the CSP exception *and* a
  render-blocking third-party round trip — see
  [../suggestions/07.asset-and-bundle-weight.md](../suggestions/07.asset-and-bundle-weight.md).
- **`frame-ancestors 'none'` conflicts with embedding the site in an iframe on
  your portfolio page.** If the portfolio shows a live preview iframe, use
  `frame-ancestors 'self' https://<your-portfolio-domain>` instead of `'none'`.
