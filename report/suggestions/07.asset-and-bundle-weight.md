# 07 · 11 MB of Images, a 1.4 MB Favicon, and No Code Splitting

| Field | Value |
|---|---|
| **Impact** | 🔴 High — this is the most visible problem after the token |
| **Effort** | ~2 hours |
| **Portfolio value** | Very high — a recruiter's first impression is load time, and Lighthouse is a number you can put in the README |

## 7a. The favicon is a 1.4 MB PNG, mislabelled as SVG

```html
<!-- client/index.html:5-9 -->
<link rel="icon" type="image/svg+xml" href="./src/assets/github-logo-cropped.png" />
```

Two problems in one tag:

- `github-logo-cropped.png` is **1.4 MB**. A favicon. Downloaded on every page
  load, on every device, before anything useful renders.
- `type="image/svg+xml"` declares a PNG as SVG. Browsers sniff and recover, but
  it is wrong and it is in the first ten lines a reviewer reads.

**Fix:** generate a proper favicon set (32×32 PNG ≈ 2 kB, or an SVG ≈ 1 kB) into
`client/public/` and reference it from the root:

```html
<link rel="icon" type="image/png" sizes="32x32" href="/favicon-32.png" />
<link rel="apple-touch-icon" sizes="180x180" href="/apple-touch-icon.png" />
```

Note also that `./src/assets/…` in `index.html` relies on Vite's build-time
rewriting. Files in `public/` are copied verbatim and referenced from `/`,
which is the correct home for a favicon.

## 7b. Measured asset inventory

```

  github-logo.png                2.0 MB   ← unused
  website_logo_1_original.png    2.0 MB   ← unused
  website_logo_3_original.png    2.0 MB   ← unused
  github-logo-cropped.png        1.4 MB   ← favicon
  website_logo_3.png             536 KB   ← navbar (dark)
  website_logo_1.png             496 KB   ← navbar (light)
  react.svg                        8 KB   ← unused
client/public/vite.svg                    ← unused
extra/
  home-design.png                1.5 MB
  profile info.png               1.4 MB
  userInfo-design.png            1.4 MB
  userNotFound-design.png        988 KB
  project-info.pdf                92 KB
```

**~6 MB of the `assets/` folder is never imported** — verified by grepping every
`assets/` reference in `client/src` and `index.html`; only
`website_logo_1.png`, `website_logo_3.png`, and the favicon appear.

The two navbar logos are **496 KB and 536 KB** for an image rendered at
**120×50 CSS pixels** ([`Navbar.tsx:22-28`](../../client/src/components/Navbar.tsx#L22)).
At 2× DPI that needs a 240×100 image — roughly 8 kB as WebP. You are shipping
**60× more bytes than the display needs**, and both logos load regardless of
theme because both are statically imported.

**Fix:**

1. Delete the four unused images and `react.svg` / `vite.svg` (−6 MB).
2. Resize the navbar logos to 240×100, export as WebP with a PNG fallback
   (−1 MB → ~16 kB).
3. Add `width`/`height` (already present — good, prevents layout shift) and
   `loading="eager"` for the navbar, `decoding="async"`.
4. Move `extra/` out of the repo or into `docs/` with compressed images — see
   [12.repo-hygiene-and-dead-code.md](12.repo-hygiene-and-dead-code.md).

## 7c. No route-level code splitting

[`App.tsx`](../../client/src/App.tsx) imports all five pages statically, so the
initial bundle contains the repo-detail page, the contribution chart, and the
explorer even for a visitor who only sees the home screen.

```tsx
const Explorer = lazy(() => import("./page/Explorer"));
const LinkWrapper = lazy(() => import("./page/LinkWrapper"));
const ShowSelectedRepo = lazy(() => import("./page/ShowSelectedRepo"));

<Suspense fallback={<PageSkeleton />}>
  <Routes>…</Routes>
</Suspense>
```

Biggest win: `ContributionChart` and its two children are only needed on a
profile page, and `@mui/icons-material` is imported piecewise across nine files.

## 7d. Google Fonts is a render-blocking third-party request

```html
<!-- client/index.html:10-19 -->
<link rel="preconnect" href="https://fonts.googleapis.com" />
<link href="https://fonts.googleapis.com/css?family=Roboto:300,400,500,700&display=swap" rel="stylesheet" />
```

The `preconnect` hints are correct — but this still costs a DNS lookup, a TLS
handshake, and a blocking stylesheet on a third-party origin, and it forces a
CSP exception ([`../vulnerabilities/04.missing-security-headers.md`](../vulnerabilities/04.missing-security-headers.md)).

Four weights of Roboto are requested; MUI's default theme uses 300/400/500/700,
so all four are genuinely referenced — but the app's own typography is heavily
`monospace` (nine components set `fontFamily: "monospace"`). Self-host with
`@fontsource/roboto` and import only the weights you use:

```ts
import "@fontsource/roboto/400.css";
import "@fontsource/roboto/500.css";
```

Same-origin, cache-friendly, one fewer CSP exception.

## 7e. No bundle visibility

Add a size check you can actually cite:

```bash
npm i -D rollup-plugin-visualizer
```

```ts
// client/vite.config.ts
import { visualizer } from "rollup-plugin-visualizer";
export default defineConfig({
  plugins: [react(), visualizer({ filename: "stats.html", gzipSize: true })],
  build: { chunkSizeWarningLimit: 600 },
});
```

Then put the Lighthouse score in the README. "98 Performance" is a concrete
claim; "optimized for performance" is not.

## Contradictions & trade-offs

- **Deleting `extra/` conflicts with
  [08.readme-and-portfolio-polish.md](08.readme-and-portfolio-polish.md)**,
  which wants screenshots in the README. Resolution: compress those four PNGs
  (1.4 MB → ~150 kB each) and move them to `docs/screenshots/`. They are design
  mockups, so they belong in documentation, not the app bundle. Note they are
  **not** in `client/src`, so they never reach the bundle today — this is repo
  weight (clone time), not page weight.
- **`git rm` does not shrink the clone.** Those 11 MB stay in history forever
  unless you rewrite it, which breaks every existing clone and fork. For a
  portfolio repo, just delete them going forward and accept the history.
- **Lazy routes add a flash of fallback on first navigation.** With chunks this
  small the delay is negligible on broadband and noticeable on 3G. Pair with
  `<link rel="modulepreload">` or route prefetch on link hover.
- **Self-hosted fonts increase your own bundle** by ~40 kB per weight while
  removing a third-party request. Net win for LCP and CSP, net loss for
  first-byte-of-JS. Worth it here.
- **Do not delete `website_logo_*_original.png` if they are your only source
  files** — they are the masters you would resize *from*. Move them out of the
  repo (or into `docs/`) rather than deleting outright.
