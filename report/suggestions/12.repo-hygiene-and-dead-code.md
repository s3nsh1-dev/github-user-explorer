The `Explorer` block is the worst: eight lines of dead JSX sitting inside the
render tree, plus its now-unused `style4`. Git is the history — delete it.

**`useFetchReposPerPage.ts:34` is not cosmetic.** The commented-out `staleTime`
means the repositories list refetches on every pagination click while its six

see [`../vulnerabilities/07.rate-limit-exhaustion.md`](../vulnerabilities/07.rate-limit-exhaustion.md).

## 12d. Unused props threaded through components

```tsx
// UserCards.tsx:10 — destructures 3 of 4 props
const UserCards: FC<UserCardsProps> = ({ userName, imageURL, githubURL }) => {
```

`seeRepos` is declared in `UserCardsProps`
([`common.types.ts:70-75`](../../client/src/constants/common.types.ts#L70)) and
passed from [`Explorer.tsx:85`](../../client/src/page/Explorer.tsx#L85) — but
never used. `noUnusedLocals` does not flag it because the property is simply not
destructured.

Similarly, [`UserProfileRepos.tsx:47-49`](../../client/src/components/UserProfileRepos.tsx#L47)
passes router state that nothing reads:

```tsx
navigate(`/user/${repo.full_name}`, { state: { repoName, username } });
```

`ShowSelectedRepo` reads both values from `useParams()`, not from `location.state`.
Drop the state object — and while you are there, build the path explicitly from
`owner` and `name` rather than relying on `full_name` containing a `/` that the
router splits into two segments (see
[`../vulnerabilities/03.api-url-tampering.md`](../vulnerabilities/03.api-url-tampering.md)).

## 12g. Inconsistent style-object placement

Some components hoist style objects to module scope
([`Explorer.tsx:10-28`](../../client/src/page/Explorer.tsx#L10),
[`ProfileInfo.tsx:14-28`](../../client/src/page/ProfileInfo.tsx#L14)) — good,
they are allocated once. Others build them inline on every render
([`UserCards.tsx:14-19`](../../client/src/components/UserCards.tsx#L14),
[`StaredRepositories.tsx:43-51`](../../client/src/components/StaredRepositories.tsx#L43)).
And `ProfileInfo` does both — `style3` is defined *inside* the component
([line 32](../../client/src/page/ProfileInfo.tsx#L32)) because it depends on
`mode`, which is correct, but it sits alongside four module-scope siblings with
no visual distinction.

Pick one convention: module scope for static styles, a `useMemo`'d object or
theme callback for mode-dependent ones.

## Contradictions & trade-offs

- **Deleting `useFetchSearchUsers` directly contradicts
  [05.search-ux-and-debounce.md](05.search-ux-and-debounce.md)**, which
  repurposes it as the single-shot query behind debounced search suggestions.
  **Decide the feature first.** If suggestions are not on the roadmap, delete
  it; leaving an unused hook that duplicates `useInfiniteUsers` is worse than
  either choice.
- **The `stared` → `starred` rename touches nine files.** Do it as an isolated
  commit with zero behavioural change, or it will bury the real diff in
  [06.starred-users-state.md](06.starred-users-state.md).
- **Renaming `hirable` → `hireable` changes the public shape of `GitHubUser`**,
  which `mapGitHubResponse` produces and `ProfileInfo` consumes. Small blast
  radius, but it is an API change to your own view model — do it alongside the
  typing work in [04.api-response-type-safety.md](04.api-response-type-safety.md).
- **Deleting commented code loses context you may still want.** The `cacheTime`
  comment in `useFetchUserData` explains a real v4→v5 rename (`cacheTime` →
  `gcTime`). If it is worth knowing, make it a real config value with a real
  comment — not a commented-out block.
- **Removing `guide.txt` erases a nice piece of project narrative.** It shows
  planning and iteration. Consider a `docs/PROJECT_LOG.md` instead of deletion —
  same content, framed deliberately.
