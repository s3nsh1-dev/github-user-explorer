Two structural improvements over the design sketched here: **every parameter
travels in the query string**, so there is no path for a proxy to reassemble
(the reintroduction risk this doc warns about), and the same-origin hop
**removed the CORS preflight** that used to double every request.

**Outstanding: none.** ✅ The now-dead `server/` folder was deleted in the
loose-ends pass after S7 — one `npm init -y` manifest, no code, referenced
nowhere ([vulnerabilities/10](../vulnerabilities/10.secret-and-dependency-hygiene.md) §10c).

## Why

Two things point the same direction:

1. [`server/package.json`](../../server/package.json) exists and is empty. The
   repo *claims* to be fullstack and isn't.
2. The GitHub token is currently compiled into the browser bundle
   ([`../vulnerabilities/01.exposed-github-token.md`](../vulnerabilities/01.exposed-github-token.md)),
   which is the single most serious problem in the codebase.

One change fixes both. And in an interview, "I moved the credential
server-side because Vite inlines `VITE_*` at build time" is a much better story
than any UI feature in this repo.

## Design

```
Browser ──► /api/users/:login          ──► GitHub REST
        ──► /api/users/:login/repos    ──► GitHub REST
        ──► /api/search/users?q=       ──► GitHub REST
        ──► /api/repos/:owner/:name    ──► GitHub REST
        ──► /api/contributions/:login  ──► GitHub GraphQL  (query lives on the server)
        ──► /api/owner-type/:login     ──► GitHub GraphQL  (query lives on the server)
```

Non-negotiables:

- **The client never sends a GraphQL document.** It sends `:login`. The server
  owns the query string and passes the login as a **GraphQL variable**. A proxy
  that forwards a client-supplied `query` is exactly as vulnerable as today's
  code, with a secret token behind it — see
  [`../vulnerabilities/02.graphql-query-injection.md`](../vulnerabilities/02.graphql-query-injection.md).
- **Validate `:login` and `:name` against the GitHub grammar** before building
  any upstream URL, and `encodeURIComponent` regardless
  ([`../vulnerabilities/03.api-url-tampering.md`](../vulnerabilities/03.api-url-tampering.md)).
- **Allow-list the upstream paths.** No generic `/api/gh/*path` passthrough —
  that reintroduces endpoint redirection with a live token.
- **Cache and rate-limit at the proxy.** All visitors now share one token
  ([`../vulnerabilities/07.rate-limit-exhaustion.md`](../vulnerabilities/07.rate-limit-exhaustion.md)).
- **Lock CORS** to your deployed origin, not `*`.

## Sketch (Express)

```js
// server/src/github.js
const GITHUB = "https://api.github.com";
const LOGIN = /^[a-zA-Z0-9](?:[a-zA-Z0-9]|-(?=[a-zA-Z0-9])){0,38}$/;
const REPO  = /^[A-Za-z0-9_.-]{1,100}$/;

const gh = (path, init = {}) =>
  fetch(`${GITHUB}${path}`, {
    ...init,
    headers: {
      Accept: "application/vnd.github+json",
      Authorization: `Bearer ${process.env.GITHUB_TOKEN}`,   // server-only, no VITE_ prefix
      "X-GitHub-Api-Version": "2022-11-28",
      ...init.headers,
    },
  });

const OWNER_TYPE = `query ($login: String!) { repositoryOwner(login: $login) { __typename } }`;

app.get("/api/owner-type/:login", async (req, res) => {
  const { login } = req.params;
  if (!LOGIN.test(login)) return res.status(400).json({ error: "invalid login" });

  const upstream = await gh("/graphql", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ query: OWNER_TYPE, variables: { login } }),   // ← variable, not interpolation
  });

  const json = await upstream.json();
  if (json.errors?.length) return res.status(502).json({ error: "upstream error" });   // don't forward detail
  res.set("Cache-Control", "public, max-age=300").json(json.data);
});
```

Add `express-rate-limit` (60 req/min per IP) and an LRU cache keyed by upstream
path with a 5-minute TTL. Two dependencies, maybe 40 lines.

## Hosting

**Recommendation: serverless functions, not a long-running Node process.**
Deploy `server/` as Vercel or Netlify functions alongside the static client, so:

- the client and API share an origin → no CORS config, and
  `connect-src 'self'` in the CSP ([`../vulnerabilities/04.missing-security-headers.md`](../vulnerabilities/04.missing-security-headers.md))
  becomes trivially correct;
- no cold-start delay on a free tier — a sleeping Render/Railway instance means
  your portfolio demo takes 10+ seconds on first click, which is a worse
  first impression than the vulnerability being fixed.

If you want the Express version for the résumé line, keep it: run Express
locally, and export the same handlers as functions in production.

## Client changes

Every hook's URL becomes relative, and the `Authorization` header disappears:

```ts
const res = await fetch(`/api/users/${encodeURIComponent(username)}`);
```

Add a dev proxy so `npm run dev` still works:

```ts
// client/vite.config.ts
export default defineConfig({
  plugins: [react()],
  server: { proxy: { "/api": "http://localhost:3000" } },
});
```

## Contradictions & trade-offs

- **This is incompatible with the "just drop the token" alternative** in
  [`../vulnerabilities/01`](../vulnerabilities/01.exposed-github-token.md).
  Going token-free is a one-hour change but deletes the contribution graph, the
  best-looking feature on the site. Pick one and commit — doing half of each
  leaves the token exposed.
- **Adds a second thing that can be down.** Today the site works as long as
  GitHub works. After this, it also needs your function to be deployed and its
  env var set. Note the `5286e2c correcting deployed site` commit — a missing
  env var has already cost you a broken deploy once.
- **The proxy centralises the rate limit.** Per-visitor limits become a single
  shared 5,000/hr pool. Ship the cache in the same change, not later.
- **Local development gets a second process.** `npm run dev` in two terminals,
  or a `concurrently` script at the root — which is another reason to do the
  workspaces cleanup in
  [`../vulnerabilities/10.secret-and-dependency-hygiene.md`](../vulnerabilities/10.secret-and-dependency-hygiene.md).
- **Don't forward upstream error bodies.** Tempting for debugging, and it
  reopens [`../vulnerabilities/09.error-message-disclosure.md`](../vulnerabilities/09.error-message-disclosure.md)
  with a secret behind it.
