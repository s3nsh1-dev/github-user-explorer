## 9a. Icon buttons have no accessible name

Every `IconButton` in the app renders an icon and nothing else, so its
accessible name is empty. A screen reader announces "button" with no indication
of what it does.

| Component | Control | Announced as |
|---|---|---|
| [`Pagination.tsx:68-88`](../../client/src/components/Pagination.tsx#L68) | first / prev / next / last page | "button" ×4 |
| [`UserProfileHeader.tsx:49`](../../client/src/components/UserProfileHeader.tsx#L49) | star / unstar profile | "button" |
| [`ShowSelectedRepo.tsx:76`](../../client/src/page/ShowSelectedRepo.tsx#L76) | back navigation | "button" |
| [`StaredRepositories.tsx:41-54`](../../client/src/components/StaredRepositories.tsx#L41) | starred-users dropdown | "button" (chevron only, when nothing is selected) |

```tsx
<IconButton aria-label="Go to first page" onClick={…}><FirstPageIcon /></IconButton>

<IconButton
  aria-label={isStarred ? `Unstar ${username}` : `Star ${username}`}
  aria-pressed={isStarred}
  onClick={…}
>
```

`PageButton` ([`PageButton.tsx:48-50`](../../client/src/components/PageButton.tsx#L48))
does render its number as text, so it has a name — but it needs
`aria-current="page"` on the active one, since the only cue today is colour.

## 9b. `PageQuickButtons` is a button that should be a link

```tsx
// PageQuickButtons.tsx:11-20
const handleClick = () => navigate(link);
return <IconButton onClick={handleClick} disabled={disabled}>{icon}</IconButton>;
```

Pagination navigates to real URLs. Rendering it as a `<button>` means no
middle-click, no ⌘-click to open in a new tab, no visible URL on hover, and no
`link` role. `IconButton` accepts `component={RouterLink} to={link}` — one prop
gets all of that back. Same for
[`PageButton.tsx:43-45`](../../client/src/components/PageButton.tsx#L43) and
[`UserProfileStats.tsx:26-28`](../../client/src/components/UserProfileStats.tsx#L26).

## 9c. Disabled buttons used as static stat cards

```tsx
// UserProfileStats.tsx:38-50
<Button variant="contained" sx={style2} disabled>
  <Typography>{userProfile.followers}</Typography>
  <Typography>Followers</Typography>
</Button>
```

Followers and Following are rendered as **disabled buttons** purely to match the
visual style of the clickable "Public Repos" card. A disabled control is removed
from the tab order and announced as unavailable, and the greyed-out styling
means the follower count itself may fail contrast requirements. These are not
controls — they are data. Use `<Paper>` or `<Card>` and style it to match.

## 9d. The search input has no label

```tsx
// LowerHomeUI.tsx:56-68
<TextField id="outlined-basic" variant="outlined" placeholder="Enter the GitHub username..." />
```

A `placeholder` is not a label: it disappears on focus, is not reliably
announced, and typically fails contrast. Add `label="GitHub username"` (MUI
wires up `<label for>` automatically) or `aria-label` if the visual label is
unwanted. Also rename the copy-pasted `id="outlined-basic"`.

The form is `noValidate` ([line 54](../../client/src/components/LowerHomeUI.tsx#L54))
with validation via `alert()` — replace with `aria-describedby` + `helperText`
so the error is announced. See
[05.search-ux-and-debounce.md](05.search-ux-and-debounce.md).

## 9e. The contribution grid is invisible to assistive tech

```tsx
// UserContributions.tsx:60-76
<Box sx={{ backgroundColor: day.color, width: "20px", height: "20px" }}>
  {day.contributionCount}
</Box>
```

365 bare `<div>`s. No date, no per-cell label, no table semantics. The count is
rendered as text at `0.7rem` in `#fffff0` on GitHub's green scale — on the
lightest cells (`#ebedf0`) that is near-invisible for everyone, not just screen
reader users.

```tsx
<Box
  role="gridcell"
  aria-label={`${day.contributionCount ?? 0} contributions on ${day.date}`}
  title={`${day.contributionCount ?? 0} contributions on ${day.date}`}
/>
```

Wrap the whole grid in `role="grid"` with an `aria-label`, and drop the visible
number in favour of the tooltip — that is what GitHub itself does, and it looks
better too.

## 9f. Colour contrast

Several hardcoded pairs need checking against WCAG AA (4.5:1 for body text):

- `#fffff0` on the lightest contribution colours — [`UserContributions.tsx:67`](../../client/src/components/UserContributions.tsx#L67)
- Grey `>>> username <<<` on `#e0e0e0` light background — [`ShowColorChangingUserName.tsx:18`](../../client/src/components/ShowColorChangingUserName.tsx#L18)
- `#FFD700` gold on `#e0e0e0` in light mode — [`PageButton.tsx:29`](../../client/src/components/PageButton.tsx#L29) and the theme's hover state
- `text.secondary: "#555"` on `#e0e0e0` — [`muiCustomTheme.ts:21`](../../client/src/theme/muiCustomTheme.ts#L21) — roughly 6.4:1, passes; `#bdbdbd` on `#23272b` in dark mode is the tighter one

## 9g. No focus-visible styling, no skip link, no landmarks

`CssBaseline` gives browser defaults, but the diamond-clipped `PageButton`
(`clipPath: polygon(...)`) will clip its own focus ring. Add an explicit
`&:focus-visible { outline: 2px solid …; outline-offset: 2px; }`.

The app has no `<main>` element — everything renders into a `<div id="root">`
with an `AppBar` on top. Wrap `<Routes>` in `<Box component="main">`.

## 9h. `alt` text

`UserCards` uses `alt="User-Profile-Picture"` for every avatar
([line 32](../../client/src/components/UserCards.tsx#L32)) — identical for all
of them, so a screen reader reads the same string 20 times. Use
`alt={`${userName}'s avatar`}`. `UserProfileHeader` already does this correctly
([line 43](../../client/src/components/UserProfileHeader.tsx#L43)) — good.

## Contradictions & trade-offs

- **9c conflicts with the current visual design.** The three stat cards look
  uniform *because* they are all `Button`s. Making two of them `Paper` means
  re-matching padding, elevation, and hover states by hand. Worth it, but it is
  a design task, not a one-line fix.
- **9b (links instead of buttons) conflicts with `disabled`.** Anchors cannot be
  disabled — you must conditionally render a non-interactive element or use
  `aria-disabled` + `pointer-events: none`. MUI handles this if you pass
  `component={RouterLink}` and swap to a plain `IconButton` when disabled.
- **9e's tooltip-instead-of-number changes the look of the signature feature.**
  Removing the digits makes it match GitHub exactly — cleaner, but less
  obviously "custom-built". Your call; the contrast problem needs solving either
  way.
- **Adding `jsx-a11y` will fail the lint on first run**, same caveat as
  [`../vulnerabilities/08.reverse-tabnabbing.md`](../vulnerabilities/08.reverse-tabnabbing.md).
  Land it after the fixes, or start with `warn`.
