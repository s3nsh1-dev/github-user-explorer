## 5a. `alert()` for form validation

```tsx
// client/src/components/LowerHomeUI.tsx:28-31
if (searchTerm.length <= 2) {
  alert("Please enter at least 3 characters to search for a user.");
  return;
}
```

A native modal `alert()` blocks the main thread, cannot be styled, looks broken
on mobile, and is the single clearest "student project" tell in the codebase.
Replace with MUI's built-in field error state:

```tsx
const [error, setError] = useState<string | null>(null);

<TextField
  error={Boolean(error)}
  helperText={error ?? " "}      // reserve the space so layout doesn't jump
  value={searchTerm}
  onChange={(e) => { setSearchTerm(e.target.value); setError(null); }}
/>
```

## 5b. There is a validation bug hiding in that block

```tsx
const trimUserName = searchTerm.trim();
if (searchTerm.length <= 2) { … }        // ← checks the UNTRIMMED length
navigate(`/explore?query=${trimUserName}`);
```

It validates `searchTerm` but navigates with `trimUserName`. Type `"  a  "` —
length 5, passes the check — and the app navigates to `?query=a`, a
single-character search that the guard was written to prevent. Validate the
trimmed value.

Also note `navigate(\`/explore?query=${trimUserName}\`)` does not encode the
query — see
[`../vulnerabilities/03.api-url-tampering.md`](../vulnerabilities/03.api-url-tampering.md).
Use `createSearchParams`:

```tsx
navigate({ pathname: "/explore", search: `?${createSearchParams({ query: trimmed })}` });
```

## 5c. Where debouncing actually belongs

Search currently fires on **submit**, not on keystroke — which is already the
right call, and better than the debounced-search-on-type the guide describes.
Debouncing an on-submit search would do nothing.

The place debouncing genuinely helps is **live suggestions**. If you add the
in-profile search box, make it a `<Autocomplete>` with debounced suggestions:

```ts
// client/src/hooks/useDebouncedValue.ts
export function useDebouncedValue<T>(value: T, delay = 400): T {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const id = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(id);
  }, [value, delay]);
  return debounced;
}
```

```tsx
const debouncedTerm = useDebouncedValue(term, 400);
const { data } = useQuery({
  queryKey: qk.searchUsers(debouncedTerm),
  queryFn: () => githubFetch(searchUrl(debouncedTerm)),
  enabled: debouncedTerm.trim().length >= 3,
});
```

400 ms is the right order of magnitude against GitHub's **10 searches/minute
unauthenticated / 30 authenticated** ceiling
([`../vulnerabilities/07.rate-limit-exhaustion.md`](../vulnerabilities/07.rate-limit-exhaustion.md)).
Without the debounce, typing "torvalds" fires 8 requests and exhausts the
unauthenticated budget in one word.

This is also where the currently-unused
[`useFetchSearchUsers`](../../client/src/hooks/useFetchSearchUsers.ts) hook
finally earns its place — it is the single-shot search that suggestions need,
while `useInfiniteUsers` stays for the results page.

## 5d. `Explorer` searches for a literal sentinel

```tsx
// client/src/page/Explorer.tsx:41
useInfiniteUsers(query || "noQueryToSearch");
```

Landing on `/explore` with no `?query=` sends GitHub a real search for the
string `"noQueryToSearch"` and renders "Matching Results : 0". Show an empty
state with the search box instead — see
[10.empty-and-notfound-states.md](10.empty-and-notfound-states.md).

## Contradictions & trade-offs

- **Directly contradicts
  [12.repo-hygiene-and-dead-code.md](12.repo-hygiene-and-dead-code.md)**, which
  recommends deleting `useFetchSearchUsers` as dead code. **Decide first:**
  build suggestions (keep and fix it) or not (delete it). Do not fix a file you
  are about to remove.
- **A navbar search box costs vertical space on mobile.** The navbar is already
  logo + theme switch; a third element at 375 px wide needs a collapse-to-icon
  pattern, not a squeezed `TextField`.
- **Debounced suggestions multiply requests against the tightest rate limit in
  the API.** Only ship it with `enabled: length >= 3`, a ≥400 ms debounce, and
  `staleTime` on the suggestion query — otherwise this suggestion actively
  worsens [`../vulnerabilities/07`](../vulnerabilities/07.rate-limit-exhaustion.md).
- **Recent-search history writes another `localStorage` key**, which inherits
  every validation concern in
  [`../vulnerabilities/06.untrusted-localstorage.md`](../vulnerabilities/06.untrusted-localstorage.md).
  Reuse the same `storage.ts` helpers.
