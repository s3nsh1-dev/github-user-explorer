# D02 · Placeholder strings assert things the API never said

| Field | Value |
|---|---|
| **Found** | 2026-08-08, during the before/after documentation pass |
| **Severity** | 🟢 Cosmetic — but it is on the profile page, which is the screen people look at |
| **File** | `client/src/helper/simplifyGitHubResponse.ts` |
| **Status** | 📋 Recorded, not fixed |

---

## What I noticed

The `og-image.png` screenshot shows Linus Torvalds' profile with:

```
💼 Hireable   🧑‍💻 Busy Learning
🔗 Blog       ⏳ Coming Soon
```

GitHub returned `hireable: null` and `blog: null` for that account — meaning
**"not stated"**. The app renders those two nulls as claims about the person.

## The code

```ts
// client/src/helper/simplifyGitHubResponse.ts:33-35
hireable: data.hireable ? "📨 Actively Applying" : "🧑‍💻 Busy Learning",
blog:     data.blog || "⏳ Coming Soon ",
```

Two things collapse into one branch:

| API value | Means | Currently renders |
|---|---|---|
| `hireable: true` | opted in to being hired | 📨 Actively Applying ✅ |
| `hireable: false` | explicitly opted out | 🧑‍💻 Busy Learning ❌ |
| `hireable: null` | never answered (most accounts) | 🧑‍💻 Busy Learning ❌ |

The same shape applies to `blog` — a null blog becomes "Coming Soon", which
implies the person is planning one.

Every other null field uses `NOT_PROVIDED` (`🚫 Not Provided`), which is
honest. These two are the outliers.

## Why it is worth a note

It is not a bug — the mapping is intentional and tested
(`simplifyGitHubResponse.test.ts:56-57` asserts both `null` and `false` produce
"Busy Learning"). It is a *content* problem: the app puts words in a real
person's mouth on a page about them. On a portfolio project someone will open
their own profile first, and "Busy Learning" when they never said so is the kind
of small wrongness that gets noticed.

There is also a trailing space in `"⏳ Coming Soon "`.

## If it ever gets fixed

```ts
hireable:
  data.hireable === true  ? "📨 Actively Applying" :
  data.hireable === false ? "🙅 Not looking" :
                            NOT_PROVIDED,
blog: data.blog || NOT_PROVIDED,
```

That is a three-line change plus updating the two test rows. It would also make
`GitHubUser.hireable` honest about having three states rather than two.

**Not doing it now** — it is a deliberate stylistic choice that was made once
already, and changing it means changing tests that currently document the
intent. Recording it so the choice is visible rather than accidental.
