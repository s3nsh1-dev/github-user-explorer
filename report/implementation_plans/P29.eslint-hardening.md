## Why

[`eslint.config.js`](../../client/eslint.config.js) extends only
`js.configs.recommended` and `tseslint.configs.recommended`, plus the React
hooks/refresh plugins. **There are no React or accessibility rules at all** —
which is why the missing `rel="noopener noreferrer"` (**P01**) and every missing
`aria-label` (**P22**) went unnoticed.

Ordering matters: this runs **after** P01 and P22-P25 have cleared the existing
violations, so the rules land green rather than producing a wall of errors I
then have to triage under pressure.

## Steps

### 1. Install

```bash
cd client && npm i -D eslint-plugin-jsx-a11y eslint-plugin-react
```

Both are dev-only and pre-approved by the index (rule 6).

### 2. Extend the flat config

```js
import jsxA11y from "eslint-plugin-jsx-a11y";
import react from "eslint-plugin-react";

// inside the existing config object:
plugins: {
  "react-hooks": reactHooks,
  "react-refresh": reactRefresh,
  "jsx-a11y": jsxA11y,
  react,
},
settings: {
  react: { version: "detect" },
  // MUI renders anchors via `component="a"` — teach the rule about them:
  linkComponents: [
    { name: "Chip", linkAttribute: "href" },
    { name: "Button", linkAttribute: "href" },
    { name: "Link", linkAttribute: "to" },
  ],
},
rules: {
  ...reactHooks.configs.recommended.rules,
  ...jsxA11y.configs.recommended.rules,
  "react/jsx-no-target-blank": ["error", { enforceDynamicLinks: "always" }],
  "react-refresh/only-export-components": ["warn", { allowConstantExport: true }],
},
```

The `linkComponents` setting is the non-obvious part — without it,
`jsx-no-target-blank` cannot see MUI's `<Chip component="a" href=...>`, which is
exactly the form that was vulnerable in `ShowSelectedRepo`.

### 3. Run and triage

```bash
npm run lint
```

Expect leftovers even after P22-P25 — likely `jsx-a11y/no-autofocus` (from
**P20**'s `autoFocus`) and possibly `anchor-is-valid`.

**Triage rule: fix the code, do not disable the rule.** The one legitimate
exception is `no-autofocus` on the home page's single search input — autofocus
on a single-purpose landing form is genuinely good UX. If I disable it, it gets
an inline `eslint-disable-next-line` **with a reason comment**, not a global off.

### 4. Verify the rules actually bite

Temporarily remove a `rel` and an `aria-label`; confirm lint fails. Restore.
A rule that does not fire is worse than no rule — it creates false confidence.

## Acceptance criteria

- [ ] Removing an `aria-label` from an icon button → lint error
