## Why

[`LoadingSkeleton.tsx:39`](../../client/src/components/LoadingSkeleton.tsx#L39)
sets `animation: "pulse 1.5s infinite"`, but `@keyframes pulse` is defined
nowhere — [`index.css`](../../client/src/index.css) is 9 lines with no keyframes,
and the MUI theme declares none. The contribution-loading skeleton has been a
static grey grid this whole time.

Verify before fixing: `grep -rn "keyframes" client/src` → expect zero hits.

## Steps

**Pick option A** — replace the hand-rolled box with MUI's `<Skeleton>`, which
animates for free, respects the theme in both light and dark, and deletes code:

```tsx
// client/src/components/LoadingSkeleton.tsx — inner cell
<Skeleton
  variant="rounded"
  width={20}
  height={20}
  sx={{ borderRadius: "10px" }}
/>
```

Drop the `backgroundColor: "#e0e0e0"` too — it is a hardcoded light-mode grey
that looks wrong in dark mode. MUI's `Skeleton` derives its colour from the
palette.

If for some reason `<Skeleton>` does not fit the 52×7 grid layout, fall back to
option B — define the keyframes in the theme so they are available app-wide:

```ts
// muiCustomTheme.ts → components.MuiCssBaseline.styleOverrides
"@keyframes pulse": {
  "0%, 100%": { opacity: 1 },
  "50%": { opacity: 0.4 },
},
```

Prefer A.
