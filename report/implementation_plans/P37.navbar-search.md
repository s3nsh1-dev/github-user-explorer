## Decision and reasoning

You left this to me. **Building it.** Three reasons:

1. **It's a real dead end.** Once a visitor is on `/user/torvalds` there is *no
   way to search again* except clicking the logo back to home and starting over.
   The navbar is logo + theme switch, nothing else. A reviewer browsing profiles
   hits this within about thirty seconds.
2. **It was already on your own list.** `guide.txt`: *"A userSearch box in the
   User profile so that another search can be done while viewing a user
   profile"* — planned, never built.
3. **It pays for itself twice.** The shared `<SearchBar>` also fills the empty
   state on `/explore` and the 404 page from **P16**, both of which currently
   have nothing useful to offer.

**Explicitly NOT building:** live autocomplete / suggestions-as-you-type. That
needs a debounced query against GitHub's tightest endpoint (10 req/min
unauthenticated, 30 authenticated) and would make
[vulnerabilities/07](../vulnerabilities/07.rate-limit-exhaustion.md) worse. This
is a submit-only search box — same behaviour as the home form, in a second
place.

## Steps

### 1. Extract `client/src/components/SearchBar.tsx`

Lift the logic from `LowerHomeUI` as fixed in **P20** — trimmed validation,
inline `helperText` error, `createSearchParams` navigation. One prop for
presentation:

```tsx
type Props = { variant?: "hero" | "compact"; autoFocus?: boolean };
```

`hero` = the current large home-page form. `compact` = navbar sizing. Same
logic, same validation, one component.

Then **rewrite `LowerHomeUI` to use it** — otherwise there are two copies of
the validation and they will drift.

### 2. Mount in the navbar on non-home routes

```tsx
const { pathname } = useLocation();
const showSearch = pathname !== "/";
```

Hiding it on `/` avoids two search boxes stacked on the landing page.

### 3. Mobile: collapse to an icon

The navbar is already logo + theme switch. At 375 px a third element does not
fit as a `TextField`. Below the `sm` breakpoint:

- Render a search `IconButton` (`aria-label="Search"`) instead of the field
- Tapping it expands a full-width row **below** the toolbar (`<Collapse>`), pushing content down rather than overlaying it
- `Escape` and blur collapse it; autofocus the field on expand

Above `sm`, render the compact `TextField` inline.

### 4. Wire into the empty states from P16

Replace P16's placeholder "Back to search" button on the `/explore` empty state
and the 404 page with a real `<SearchBar variant="hero" />`. P16 deliberately
left this as a follow-up.

### 5. Accessibility

Inherits **P20**'s real `<label>` and **P22**'s conventions. The mobile toggle
needs `aria-expanded` and `aria-controls` pointing at the collapsible region.

## Acceptance criteria

- [ ] Search from a profile page → navigates to `/explore?query=…` with correct encoding
- [ ] Not rendered on `/`
- [ ] 375 px: icon only; tap expands; Escape collapses; layout does not overflow horizontally
- [ ] 1440 px: inline field, navbar layout unchanged otherwise
- [ ] Validation identical to the home form (`"  a  "` rejected) — because it is literally the same component
- [ ] `grep -c "trim()" client/src/components/SearchBar.tsx` → 1, and **zero** validation logic left in `LowerHomeUI`
- [ ] 404 page and `/explore` empty state both offer a working search
- [ ] Keyboard: Tab reaches it, Enter submits, `aria-expanded` correct on mobile
- [ ] Verification gate green

## Do NOT

- **Do not add autocomplete/suggestions.** Stated in the decision above; this is the line that keeps the plan cheap and the rate limit safe.
- Do not resurrect `useFetchSearchUsers` — deleted in **P02**, and this plan does not need a hook at all. It only navigates.
- Do not overlay the mobile field on top of the logo. Push content down; overlays trap focus and break on small screens.
- Do not add search history. Another feature, another storage key.
- **Do mention this in the docs** — you asked. It goes in the **P33** README feature list ("search from anywhere") and gets a line in `docs/PROJECT_LOG.md` marking the `guide.txt` item as done.
