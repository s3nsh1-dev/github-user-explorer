## Why

`localStorage` is writable by the user, by any extension, and by every past
version of the app. Two places read it as trusted internal state:

```ts
// StaredUserContextProvider.tsx:9-11 — no try/catch
const initialList: string[] = JSON.parse(localStorage.getItem("staredProfiles") || "[]");

// ModeContextProvider.tsx:6 — `as` is an assertion, not a check
const localStorageValue = localStorage.getItem("mode") as ModeType;
```

Malformed JSON throws **during render** on the home page's first paint. A
non-array that parses (`"5"`) throws later at `staredList.map`. And a `mode` of
`"purple"` produces an incoherent half-dark theme, because the codebase compares
against `"dark"` in some places and `"light"` in others.

The stored values also flow into route params → into API requests, making
storage a second, persistent injection source for **P07**/**P08**.

## Steps

### 1. `client/src/helper/storage.ts`

```ts
import { isValidLogin } from "./validateLogin";

const STARRED_KEY = "staredProfiles";   // keep the existing key — renaming it drops users' data

export const readStarred = (): string[] => {
  try {
    const parsed: unknown = JSON.parse(localStorage.getItem(STARRED_KEY) ?? "[]");
    if (!Array.isArray(parsed)) return [];
    return [...new Set(parsed.filter(isValidLogin))];
  } catch {
    return [];
  }
};

export const writeStarred = (list: string[]): void => {
  try {
    localStorage.setItem(STARRED_KEY, JSON.stringify(list));
  } catch {
    /* QuotaExceededError, or Safari private mode */
  }
};

export const readMode = (): ModeType => {
  const v = localStorage.getItem("mode");
  if (v === "light" || v === "dark") return v;
  return window.matchMedia?.("(prefers-color-scheme: dark)").matches ? "dark" : "light";
};

export const writeMode = (mode: ModeType): void => {
  try { localStorage.setItem("mode", mode); } catch { /* ignore */ }
};
```

`parsed.filter(isValidLogin)` works cleanly because **P04** made it a type
predicate — the result is `string[]` with no cast.

`writeStarred` is wrapped because `setItem` genuinely throws on quota exhaustion
and in some private-browsing modes.

### 2. Wire into `ModeContextProvider` only

```ts
const [mode, setMode] = useState<ModeType>(readMode);   // lazy initialiser
const handleSettingMode = (newMode: ModeType) => { setMode(newMode); writeMode(newMode); };
```

## ⚠️ Behaviour changes to expect

- **First-time visitors now get the system theme** instead of always-light. Desirable, but it changes what the app looks like on first load — relevant to any README screenshot (**P33**).
- **Starred entries that fail `isValidLogin` are silently dropped** on first read after deploy. Intended, but it is data loss. Acceptable here; worth stating in the commit message.
