## Steps

### 1. Check the SPA fallback first — it may already be broken

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://github-userexplorer.netlify.app/user/torvalds
```

`200` → a redirect rule already exists in the Netlify UI (undocumented and
unversioned — still move it into the repo). `404` → **deep links are broken
right now**, and this is the highest-impact part of the plan: every profile
link you share fails on load.

### 2. Extend `netlify.toml` (created in P34)

```toml
[[redirects]]
  from = "/api/*"
  to   = "/.netlify/functions/:splat"
  status = 200
  force = true

# SPA fallback — MUST come after /api/*, or it swallows the function routes.
[[redirects]]
  from = "/*"
  to   = "/index.html"
  status = 200

[[headers]]
  for = "/*"
  [headers.values]
    Content-Security-Policy = "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com; img-src 'self' data: https://*.githubusercontent.com; connect-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'none'; object-src 'none'"
    X-Content-Type-Options = "nosniff"
    Referrer-Policy = "strict-origin-when-cross-origin"
    Permissions-Policy = "camera=(), microphone=(), geolocation=()"

[[headers]]
  for = "/assets/*"
  [headers.values]
    Cache-Control = "public, max-age=31536000, immutable"

[[headers]]
  for = "/index.html"
  [headers.values]
    Cache-Control = "public, max-age=0, must-revalidate"
```

**Redirect order is load-bearing.** Netlify evaluates top-down; `/*` above
`/api/*` would serve `index.html` for every API call.

### 3. CSP notes — each of these will break the site if got wrong

- **`connect-src 'self'`** and **not** `api.github.com` — correct *only after* **P34** lands. Before that, the client still calls GitHub directly and this directive breaks every request. **Do not ship this plan before P34.**
- **`style-src 'unsafe-inline'` is mandatory.** Emotion (MUI's engine) injects styles at runtime. Removing it blanks the entire UI. `script-src 'self'` with no `'unsafe-inline'` is the directive actually doing the work.
- **`img-src https://*.githubusercontent.com`** — avatars. Without it every avatar breaks.
- **`frame-ancestors 'none'`** — change to `'self' https://<your-portfolio-domain>` if you ever embed a live preview iframe.
- Google Fonts is still allowed. Self-hosting via `@fontsource/roboto` (**B9**, still open) would let both font exceptions be dropped.

### 4. Anti-flash theme script — CSP-safe

[suggestions/13](../suggestions/13.deployment-config.md) §13d proposes an inline
`<head>` script so dark-mode visitors do not get a white flash. It needs a
**SHA-256 hash** in `script-src`, not `'unsafe-inline'`:

```bash
printf '%s' '<script contents without the tags>' | openssl dgst -sha256 -binary | openssl base64
```

Then append `'sha256-<digest>'` to `script-src`. **If the hash is fiddly, skip
the script entirely** — a brief white flash is a far smaller problem than
weakening `script-src`. It must also agree with `readMode()` from **P17** on the
`prefers-color-scheme` fallback, or the pre-paint colour and React's chosen
theme disagree and you get a flash in the opposite direction.

## Acceptance criteria

- [ ] `/user/torvalds` returns 200 on a hard refresh (deep links work)
- [ ] All four security headers present in `curl -I`
- [ ] **Zero CSP violations** in the browser console across home, explore, profile, repo detail
- [ ] Avatars, fonts, and the contribution grid all render
- [ ] `/api/*` reaches the functions, not `index.html`
- [ ] Link preview renders in Slack/Discord (paste it to yourself)
- [ ] securityheaders.com grade A or better
- [ ] Verification gate green

## Do NOT

- **Do not ship before P34.** `connect-src 'self'` breaks a client that still calls `api.github.com` directly.
- Do not add `'unsafe-inline'` to `script-src`. Hash the theme script or drop it.
- Do not remove `'unsafe-inline'` from `style-src`. MUI stops rendering.
- Do not put `/*` above `/api/*` in the redirects.
- Do not commit a `vercel.json` as well. One host, one config file.
