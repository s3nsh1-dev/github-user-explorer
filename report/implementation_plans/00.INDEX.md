### What S3 changed that later plans must account for

- **`constants/schemas.ts` is the source of truth for every API type.** Each
  payload has a Zod schema; the type is `z.infer`red from it. `common.types.ts`
  re-exports those names, so every existing `import type … from
  "../constants/common.types"` still resolves — but **never add a hand-written
  interface for a GitHub payload again**, or the type and the check drift.
- ⚠️ **`z.object` strips undeclared keys.** A component that reads a field
  absent from the schema gets `undefined` at runtime and no compiler warning.
  Adding a field to a render means adding it to the schema.
- **`githubFetch` / `githubGraphQL` take an optional Zod schema** and validate
  with `.safeParse`. All 8 hooks pass one. A schema gap throws a `GitHubError`
  with a generic message; issue detail goes to the dev console only.
- ⚠️ **`helper/githubFetch.ts` now reads `import.meta.env` twice** — the token,
  and `import.meta.env.DEV` to gate that console log. **P34** must remove the
  first and keep the second. Grepping for `import.meta.env` no longer returns
  exactly one hit.
- **Every hook returns the full `UseQueryResult`.** `useFetchUserData`,
  `useFetchReposPerPage` and `useShowIndividualRepo` no longer destructure three
  fields, so `refetch` is available to **P13**'s Retry button. Call sites
  destructure `{ data, isLoading, error }`.
- **Query keys come from `constants/queryKeys.ts` (`qk.*`).** Never inline one.
- **`useFetchRepositories` is deleted.** `Repositories.tsx` reads `public_repos`
  from `useFetchUserData`.
- **Fetch policy is global, in `main.tsx`:** `staleTime` 5 min, `gcTime` 30 min,
  `refetchOnWindowFocus: false`, and a retry predicate that refuses on
  `RateLimitError` / `NotFoundError` and otherwise allows one retry. **No hook
  carries its own `staleTime`.** `useFetchReposPerPage` adds
  `placeholderData: keepPreviousData`.
- ⚠️ **The retry predicate depends on `assertOk` still being able to recognise a
  rate limit**, which it does by reading the `x-ratelimit-remaining` and
  `x-ratelimit-reset` **response headers**. **P34's proxy must forward those
  headers**, or every 403 degrades to a generic `GitHubError` and the app starts
  retrying into the limit again.
- **`Repositories.tsx`'s `as number` is deliberately still there** — see the S3
  report in `../branch-info.md` for why it is P15's and not P09's.
- **Bundle: 571.30 kB → 641.30 kB raw, 179.51 → 198.80 kB gzip.** Zod costs
  ~19 kB gzipped, more than the ~14 kB the suggestion doc estimated. **P26/P27**
  measure against the P00 baseline, so subtract this before reading their gain.

### What S4 changed that later plans must account for

- 🔴 **The client no longer talks to `api.github.com`.** Every request goes to
  same-origin `/api/*`, served by `netlify/functions/`. `client/src` contains
  **zero** occurrences of `api.github.com`, `Authorization` or a token read, and
  so does `dist/`. The only `import.meta.env` left is the `DEV` guard on the
  schema-mismatch log.
- **`client/src/constants/graphqlQueries.ts` is deleted.** The three documents
  live in `netlify/functions/_shared/queries.mts`. **Never reintroduce a query
  string that travels from the browser** — the proxy holds a token, so a
  client-supplied document is the pre-P08 injection with a credential behind it.
- **`githubGraphQL` is gone from `helper/githubFetch.ts`.** The three GraphQL
  hooks are ordinary `githubFetch` calls against named endpoints. Their Zod
  schemas are unchanged, because the proxy unwraps `{ data, errors }` and maps a
  GraphQL failure onto an HTTP status exactly as `githubGraphQL` used to.
- **`helper/githubUrls.ts` has seven builders now**, not four —
  `ownerTypeUrl`, `contributionsUrl` and `orgReposUrl` joined the REST four.
  Relevant to **P30**, whose highest-value tests are still the security ones.
- ⚠️ **Every parameter travels in the query string; none in a path segment.**
  That is the V03 fix at the proxy boundary, and it is structural: there is no
  path to traverse. A future endpoint must follow the same shape.
- **The proxy forwards `x-ratelimit-*` and preserves 403/404 statuses**, so
  `assertOk` still builds `RateLimitError` / `NotFoundError` and **P11**'s retry
  predicate still refuses them. Verified against a real GitHub 403.
- **`netlify.toml` exists** with `base = "client"`, an `/api/*` rewrite above the
  SPA fallback, a CSP, and cache headers. ⚠️ **Redirect order is load-bearing** —
  `/*` above `/api/*` serves `index.html` for every API call. **P26** must
  re-check that `/assets/*` still matches after it moves image masters.
- **`connect-src 'self'` is now live.** Any future feature that fetches a
  third-party origin from the browser needs a CSP change, not just code.
- **`client/package.json` gained `typecheck:functions`.** The functions are a
  separate TS project (`netlify/functions/tsconfig.json`) and are **not** covered
  by `tsc -b`. Run it alongside the gate when touching `netlify/`.
- **`netlify/functions/` has zero npm dependencies** and imports
  `client/src/helper/validateLogin.ts` directly, so the login/repo-name rules
  have one definition guarding both the browser route and the upstream request.
  Changing those regexes changes both. **P16**/**P17**/**P20** should import the
  same file rather than re-deriving.

## Working across chat sessions

You intend to run one chat instance per feature. Each plan file is written to be
self-contained for exactly that: a fresh session needs only its plan plus this
index. To hand off cleanly:

- **Start each session by naming the plan** ("implement P07"), and point it at this index for the dependency graph and the rules above.
- **Respect the dependency column.** Batch B (P04→P11) in particular is one continuous pass over the same 8 hook files; splitting it across sessions means merge conflicts with yourself.
- **Update this index when a plan lands** — add a ✅ and the commit SHA to its row, so the next session knows what is already true.
- **P00 runs once**, in the first session only.
