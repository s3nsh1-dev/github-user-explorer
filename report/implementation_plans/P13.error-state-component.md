## Why

Six places print an error value straight into an unstyled `<div>`, and one uses
`{String(error)}`. Two problems: internal implementation strings leak (including
the typo `"Response for LongType was not ok"`), and six unstyled divs drop out
of an otherwise fully themed app.

The typed errors from **P05** make proper classification possible.

## Steps

### 1. `client/src/components/ErrorState.tsx`

```tsx
const describe = (error: unknown): { title: string; body: string } => {
  if (error instanceof RateLimitError)
    return {
      title: "GitHub rate limit reached",
      body: `Too many requests. Try again after ${error.resetAt.toLocaleTimeString()}.`,
    };
  if (error instanceof NotFoundError)
    return { title: "Not found", body: "That GitHub user or repository doesn't exist." };
  return { title: "Something went wrong", body: "Couldn't load data from GitHub. Please try again." };
};

export const ErrorState = ({ error, onRetry }: { error: unknown; onRetry?: () => void }) => {
  if (import.meta.env.DEV) console.error(error);
  const { title, body } = describe(error);
  return (
    <Alert severity="error" action={onRetry && <Button size="small" onClick={onRetry}>Retry</Button>}>
      <AlertTitle>{title}</AlertTitle>
      {body}
    </Alert>
  );
};
```

**Two layers, deliberately:** the hooks *throw* detailed messages (so they reach
the console and React Query devtools), and this component *renders* a
classified generic one. That resolves the apparent contradiction between
[vulnerabilities/05](../vulnerabilities/05.unhandled-api-errors.md) and
[09](../vulnerabilities/09.error-message-disclosure.md) — both are right at
different layers.

## Acceptance criteria

- [ ] `grep -rn "error.message\|String(error)" client/src` → no hits in JSX
- [ ] Rate limit yourself (or stub a 403 with `x-ratelimit-remaining: 0`) → the reset-time message renders
- [ ] Nonexistent user → "Not found", not a raw API string
- [ ] Retry button actually refetches
- [ ] Every error state is themed and works in dark mode
- [ ] Verification gate green

## Do NOT

- Do not render `error.message` in production, ever — including "just for debugging". The `DEV` console path covers local work.
- Do not use `<ErrorState>` for *empty* results. "No repositories" is not an error — **P16**.
- Do not add an error-reporting SDK (Sentry etc.). Dependency + account decision I do not have.
