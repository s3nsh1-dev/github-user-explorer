## Why

(tests land in **P30** — this plan only creates the helper).

## Steps

Create `client/src/helper/validateLogin.ts`:

```ts
/**
 * GitHub login rules: alphanumeric plus single internal hyphens,
 * cannot start or end with a hyphen, max 39 characters.
 */
export const GITHUB_LOGIN = /^[a-zA-Z0-9](?:[a-zA-Z0-9]|-(?=[a-zA-Z0-9])){0,38}$/;

/** Repo names allow dots and underscores; max 100 characters. */
export const GITHUB_REPO_NAME = /^[A-Za-z0-9_.-]{1,100}$/;

export const isValidLogin = (value: string | undefined): value is string =>
  typeof value === "string" && GITHUB_LOGIN.test(value);

export const isValidRepoName = (value: string | undefined): value is string =>
  typeof value === "string" && value !== "." && value !== ".." && GITHUB_REPO_NAME.test(value);
```

Note the explicit `.` / `..` rejection in `isValidRepoName` — the character
class alone would accept both, and they are exactly the path-traversal segments
[vulnerabilities/03](../vulnerabilities/03.api-url-tampering.md) exploits.

The `value is string` type predicates matter: they let call sites narrow
`string | undefined` from `useParams()` without a cast, which is what makes
**P16** able to delete the `"demoUserName"` fallbacks cleanly.

### Sanity-check against real inputs before moving on

Must **pass**: `torvalds`, `s3nsh1-dev`, `a`, `x-y-z`, a 39-char string, `microsoft`
Must **fail**: `-lead`, `trail-`, `dou--ble`, a 40-char string, `""`, `undefined`,
`x/../../orgs/github`, `a") { __typename } viewer { login }`, `a&per_page=100`

Run these through `node --experimental-strip-types` or a scratch script — do not
just eyeball the regex.

## Do NOT

- Do not wire it into any component yet. P07/P16/P17/P20 each do their own wiring, deliberately, so a regression is attributable to one plan.
- Do not reach for Zod here. Zod is in use (**P28** env, **P09** API responses), but these are two well-specified grammars and a regex is the right tool. If you want them composable, wrap later as `z.string().refine(isValidLogin)` — the predicates stay the source of truth.
- Do not try to also validate search *queries* — GitHub search syntax is a whole grammar (`location:`, `followers:>100`) and must stay permissive. Encoding, not validation, is the fix there (**P07**).
