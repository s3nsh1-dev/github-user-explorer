## Why

There is **no error boundary anywhere** in
[`main.tsx`](../../client/src/main.tsx) or
[`App.tsx`](../../client/src/App.tsx). In React 19 an uncaught render error
unmounts the entire root — the visitor gets a blank white page, not a degraded
component.

**P05** removes the main known crash path (GraphQL 200-with-errors). This plan
is the safety net for the ones I have not found.

## Steps

### 1. `client/src/components/AppErrorBoundary.tsx`

Must be a class component — React still has no hook equivalent for
`getDerivedStateFromError`.

```tsx
import { Component, type ReactNode } from "react";

type Props = { children: ReactNode; fallback?: (reset: () => void) => ReactNode };
type State = { error: Error | null };

class AppErrorBoundary extends Component<Props, State> {
  state: State = { error: null };

  static getDerivedStateFromError(error: Error): State {
    return { error };
  }

  componentDidCatch(error: Error, info: unknown) {
    if (import.meta.env.DEV) console.error("Uncaught render error:", error, info);
  }

  reset = () => this.setState({ error: null });

  render() {
    if (!this.state.error) return this.props.children;
    return this.props.fallback?.(this.reset) ?? <SomethingWentWrong onRetry={this.reset} />;
  }
}
```

The `componentDidCatch` console log matters — without it, a boundary silently
swallows bugs in development and I stop seeing real errors.

### 2. `client/src/components/SomethingWentWrong.tsx`

Themed MUI fallback: heading, generic message, "Try again" button wired to
`reset`, "Back to home" link. **Do not print `error.message`** — see
[vulnerabilities/09](../vulnerabilities/09.error-message-disclosure.md).

### 3. Wrap at two levels

- **Root**, in `main.tsx`, inside `<ThemeProvider>` so the fallback is themed — note this means it goes inside `<App>`, or `ThemeProvider` must be hoisted out of `App.tsx` first. Check which is less invasive; hoisting `ThemeProvider` to `main.tsx` is probably cleaner and is a small diff.
- **Around `<ContributionChart>`** in [`ProfileInfo.tsx:127`](../../client/src/page/ProfileInfo.tsx#L127), so a broken contribution graph degrades to a card instead of taking down the whole profile page around it.

## Do NOT

- Do not install `react-error-boundary`. ~30 lines of local code vs a dependency; local wins here.
- Do not swallow errors in production without logging. No error-reporting service is configured (and adding one is a decision I do not have) — but keep the `DEV` console path so local debugging still works.
- Do not use the boundary to handle *query* errors. React Query errors are values, not throws; they get `<ErrorState>` in **P13**. Only unexpected render crashes belong here.
