## Why

Three hooks interpolate a URL-controlled param straight into a GraphQL
document. React Router percent-decodes path params, so `%22` arrives as a real
`"` and closes the string literal:

```
/user/a%22)%20%7B__typename%7D%20viewer%20%7Blogin%20email%7D%20z%3A%20repositoryOwner(login%3A%22b
```

…produces a valid document containing `viewer { login email }`, which resolves
to **the token owner**.

This is the highest-severity thing I can fix without you. (V01, the exposed
token, needs **B1**/**B2**.) Note the ordering trap: fixing V01 without this
*raises* this issue's severity — behind a proxy the token is secret again and
injection becomes the way to abuse it.

## Steps

### 1. Reproduce first

Load the PoC URL above, open the Network tab, inspect the POST body to
`api.github.com/graphql`. Confirm the injected `viewer` block is present in the
`query` string. Screenshot it for the commit message.

### 2. Extract queries to module constants with typed variables

```ts
// client/src/constants/graphqlQueries.ts
export const OWNER_TYPE_QUERY = /* GraphQL */ `
  query OwnerType($login: String!) {
    repositoryOwner(login: $login) { __typename }
  }
`;

export const CONTRIBUTIONS_QUERY = /* GraphQL */ `
  query Contributions($login: String!) {
    user(login: $login) {
      contributionsCollection {
        contributionCalendar {
          totalContributions
          weeks { contributionDays { date contributionCount color } }
        }
      }
    }
  }
`;

export const ORG_TOP_REPOS_QUERY = /* GraphQL */ `
  query OrgTopRepos($login: String!) {
    organization(login: $login) {
      repositories(first: 10, orderBy: { field: UPDATED_AT, direction: DESC }) {
        nodes { name description stargazerCount updatedAt }
      }
    }
  }
`;
```

The `/* GraphQL */` comment enables syntax highlighting and gives future tooling
a hook. Named operations (`query OwnerType`) also show up in GitHub's API logs,
which is genuinely useful.

### 3. Call through `githubGraphQL` from P05

```ts
queryFn: () => githubGraphQL<OwnerTypeData>(OWNER_TYPE_QUERY, { login: username }),
```

The value now travels in the `variables` object — **it can never be parsed as
query syntax**. That is the actual fix; everything else is hygiene.

### 4. Note the parallel obligation for a future proxy

Add a comment at the top of `graphqlQueries.ts`: if decision **B2** lands on a
backend proxy, these constants must move **server-side**, and the client must
send only `{ login }`. A proxy that forwards a client-supplied `query` string is
exactly as vulnerable as today's code, with a secret token behind it.

## Do NOT

- Do not add the `isValidLogin` gate here. Variables are the real fix; validation is defence-in-depth and belongs with the 404 page in **P16**. Landing them separately means I can tell which one broke something.
- Do not switch to a GraphQL client library (Apollo, urql, graphql-request). Massive dependency for three queries; `fetch` + variables is correct and already written.
- Do not add codegen. Types are **P09**, by hand.
