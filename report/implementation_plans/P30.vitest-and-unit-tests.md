## Why

Zero test files exist. Everything in the audit was found by reading, not by a
failing test — and several findings (the `["react", "keyIsUnique"]` collision,
`Math.ceil(undefined / 8)`) are exactly what a handful of tests would have
caught.

**Ordering is critical:** this runs *after* **P15** deliberately. Writing tests
against the current code would encode `NaN` behaviour as expected. That is
index rule 8.

## Steps

### 1. Install and configure

```bash
cd client && npm i -D vitest @testing-library/react @testing-library/jest-dom jsdom
```

```ts
// client/vite.config.ts
/// <reference types="vitest" />
export default defineConfig({
  plugins: [react()],
  test: { environment: "jsdom", setupFiles: "./src/test/setup.ts", globals: true },
});
```

```ts
// client/src/test/setup.ts
import "@testing-library/jest-dom/vitest";
```

Add `"test": "vitest"` and `"test:run": "vitest run"` to
[`client/package.json`](../../client/package.json) scripts.

Vitest reuses the existing Vite config — that is the main reason to prefer it
over Jest here (no second build pipeline, no separate transform config).

### 2. `helper/validateLogin.test.ts` — includes security regression tests

```ts
it.each(["torvalds", "s3nsh1-dev", "a", "x-y-z", "microsoft", "a".repeat(39)])
  ("accepts %s", (v) => expect(isValidLogin(v)).toBe(true));

it.each(["-lead", "trail-", "dou--ble", "a".repeat(40), "", undefined])
  ("rejects %s", (v) => expect(isValidLogin(v)).toBe(false));

it("rejects GraphQL injection payloads", () => {
  expect(isValidLogin('a") { __typename } viewer { login email }')).toBe(false);
});

it("rejects path traversal", () => {
  expect(isValidLogin("x/../../orgs/github")).toBe(false);
  expect(isValidRepoName("..")).toBe(false);
});
```

Those last two are worth pointing at — they are regression tests tied to
[vulnerabilities/02](../vulnerabilities/02.graphql-query-injection.md) and
[03](../vulnerabilities/03.api-url-tampering.md).

### 3. `helper/paginate.test.ts` — the logic that was actually broken

```ts
it.each([
  [1,  1,  [1]],
  [1,  3,  [1, 2, 3]],
  [1,  10, [1, 2, 3]],
  [9,  10, [8, 9, 10]],
  [10, 10, [8, 9, 10]],
  [1,  0,  []],      // ← would have failed pre-P15
  [1,  NaN, []],     // ← would have failed pre-P15
])("page %i of %i → %j", (page, total, expected) => {
  expect(pageWindow(page, total)).toEqual(expected);
});

it("totalPageCount handles undefined-ish input", () => {
  expect(totalPageCount(NaN)).toBe(0);
  expect(totalPageCount(0)).toBe(0);
  expect(totalPageCount(100)).toBe(13);
});
```

### 4. `helper/simplifyGitHubResponse.test.ts`

Covers null-field placeholders and the `hireable` mapping — which documents a
real behaviour: `null` and `false` both map to "Busy Learning". Intentional, but
currently undocumented.

### 5. `helper/storage.test.ts`

Malformed JSON → `[]`. Non-array → `[]`. Invalid logins filtered. Invalid `mode`
→ system default. Uses jsdom's `localStorage`; clear it in `beforeEach`.
