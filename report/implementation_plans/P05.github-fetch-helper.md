## Why

Eight hooks each hand-roll `fetch` + `if (!res.ok) throw new Error("...")`. That
pattern cannot distinguish a 404 from a rate limit, and — critically — **it does
not catch GraphQL errors at all**, because GraphQL returns HTTP 200 with
`{ data: null, errors: [...] }`. That is the crash in
[vulnerabilities/05](../vulnerabilities/05.unhandled-api-errors.md).

## Steps

### 1. Create `client/src/helper/githubErrors.ts`

```ts
export class GitHubError extends Error {
  constructor(message: string, readonly status?: number) {
    super(message);
    this.name = "GitHubError";
  }
}

export class NotFoundError extends GitHubError {
  constructor(what = "Resource") {
    super(`${what} not found`, 404);
    this.name = "NotFoundError";
  }
}

export class RateLimitError extends GitHubError {
  constructor(readonly resetAt: Date) {
    super("GitHub rate limit reached", 403);
    this.name = "RateLimitError";
  }
}
```

Use `class X extends Error` + explicit `this.name`, **not** a discriminated
union — `instanceof` is what **P11**'s retry predicate and **P13**'s renderer
need. (Note: `extends Error` subclassing works correctly here because the build
targets ES2020, not ES5.)

### 2. Create `client/src/helper/githubFetch.ts`

```ts
const TOKEN = import.meta.env.VITE_GITHUB_AUTHENTICATION_TOKEN;

const authHeaders = (): HeadersInit => ({
  Accept: "application/vnd.github+json",
  "X-GitHub-Api-Version": "2022-11-28",
  ...(TOKEN ? { Authorization: `Bearer ${TOKEN}` } : {}),
});

function assertOk(res: Response): void {
  if (res.ok) return;
  if ((res.status === 403 || res.status === 429) && res.headers.get("x-ratelimit-remaining") === "0") {
    throw new RateLimitError(new Date(Number(res.headers.get("x-ratelimit-reset") ?? 0) * 1000));
  }
  if (res.status === 404) throw new NotFoundError();
  throw new GitHubError(`GitHub API error ${res.status}`, res.status);
}

export async function githubFetch<T>(url: string | URL): Promise<T> {
  const res = await fetch(url, { headers: authHeaders() });
  assertOk(res);
  return res.json() as Promise<T>;
}

export async function githubGraphQL<T>(query: string, variables: Record<string, unknown>): Promise<T> {
  const res = await fetch("https://api.github.com/graphql", {
    method: "POST",
    headers: { ...authHeaders(), "Content-Type": "application/json" },
    body: JSON.stringify({ query, variables }),
  });
  assertOk(res);

  const json = (await res.json()) as { data: T | null; errors?: Array<{ message: string }> };

  // GraphQL reports failure in the body at HTTP 200 — this is the crash path.
  if (json.errors?.length) {
    const message = json.errors[0].message;
    if (/could not resolve to a/i.test(message)) throw new NotFoundError();
    throw new GitHubError(message);
  }
  if (json.data === null || json.data === undefined) throw new GitHubError("Empty GraphQL response");

  return json.data;   // ← returns `data`, NOT the envelope
}
```

### 3. Keep the `TOKEN` read here and ONLY here

Every hook's `import.meta.env` line goes away. That single chokepoint is what
makes decision **B2** (proxy vs token-free) a one-file change later.

The `TOKEN ? ... : {}` spread means the app degrades to unauthenticated REST
instead of sending `Bearer undefined` when the env var is missing — which is
almost certainly what broke commit `5286e2c`.

### 4. Migrate all 8 hooks to `githubFetch` / `githubGraphQL`

Mechanical. Keep each hook's existing URL string **exactly as-is for now** —
encoding is **P07**, GraphQL variables are **P08**. This plan changes the
transport only, so a regression is attributable.

### 5. ⚠️ Breaking change to fix in the same commit

`githubGraphQL` returns `data`, not the envelope. Three consumers read
`data.data.…` and must lose one hop:

- [`ContributionChart.tsx:8`](../../client/src/components/ContributionChart.tsx#L8) → `data.repositoryOwner?.__typename`
- [`UserContributions.tsx:28-32`](../../client/src/components/UserContributions.tsx#L28) → `data.user.contributionsCollection…`
- [`OrganizationTopRepos.tsx:32`](../../client/src/components/OrganizationTopRepos.tsx#L32) → `data?.organization?.repositories?.nodes`

And the envelope types in
[`common.types.ts:115-160`](../../client/src/constants/common.types.ts#L115)
(`OrganizationTop10ReposType`, `ContributionCalendarResponse`) must drop their
outer `data:` wrapper. **The build will not compile mid-way through this step —
that is expected. Finish it before running the gate.**
