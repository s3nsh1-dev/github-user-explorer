## Steps

### 1. Fix `.env.development`

```bash
GITHUB_TOKEN=xxxxx      # no space before =, no quotes, no trailing whitespace
```

### 2. Which file, and where — this bites on Netlify

- **`netlify dev` loads `.env` and `.env.<context>` from the repo root.** Root placement is right for the functions.
- **Vite loads env files from the Vite root, which is `client/`.** A root-level file is invisible to Vite. That does not matter after **P34** (the client needs no env vars at all), but it explains any confusion during the transition.
- Consider renaming to plain `.env` so both `netlify dev` and any local script pick it up without context juggling. `.gitignore` covers both.

### 3. `.env.example` at the repo root — committed

```bash
# Copy to .env and fill in. Never commit the real file.
#
# Server-side only. Read by Netlify Functions (see netlify/functions/_shared/env.mts).
# It is NOT exposed to the browser — that is the entire point of the proxy.
# Do NOT prefix it with VITE_: that would inline it into the client bundle.
# See report/vulnerabilities/01.exposed-github-token.md
#
# Scopes required: NONE. Public GitHub data needs no scopes.
GITHUB_TOKEN=
```

Verify it is not swallowed by the `.env.*` ignore rule:

```bash
git check-ignore -v .env.example    # must print nothing
```

If it is ignored, add `!.env.example` to `.gitignore`. **Check; do not assume.**

### 4. Server env schema — the Zod pattern

```ts
// netlify/functions/_shared/env.mts
import { z } from "zod";

const EnvSchema = z.object({
  GITHUB_TOKEN: z
    .string()
    .min(1, "GITHUB_TOKEN is required")
    .refine((v) => v === v.trim(), "GITHUB_TOKEN has leading/trailing whitespace")
    .refine(
      (v) => /^(ghp_|github_pat_|gho_|ghs_)/.test(v),
      "GITHUB_TOKEN does not look like a GitHub token"
    ),
});

const parsed = EnvSchema.safeParse(process.env);

if (!parsed.success) {
  // Field names only — NEVER the values.
  throw new Error(
    `Invalid environment: ${parsed.error.issues.map((i) => `${i.path.join(".")}: ${i.message}`).join("; ")}`
  );
}

export const env = parsed.data;   // fully typed: env.GITHUB_TOKEN is string
```

Three things this buys beyond typing: it fails at cold start with a *readable*
message instead of a 401 from GitHub twenty minutes later; the whitespace
`refine` catches exactly the `GITHUB_TOKEN =` bug above; and a typo in the
variable name is a startup error, not `Bearer undefined`.

⚠️ **Error messages must never include the value.** `z.error.issues` includes
`path` and `message` but `safeParse` errors can carry `input` in some
formatters — use the explicit `.map()` above, not `JSON.stringify(error)`.

### 5. Client env — there isn't one

After **P34** the client calls same-origin `/api/*` and needs **zero**
environment variables. So:

- Delete the `VITE_GITHUB_AUTHENTICATION_TOKEN` declaration from [`client/src/vite-env.d.ts`](../../client/src/vite-env.d.ts) (leave the `/// <reference types="vite/client" />` line).
- **Do not** create `client/src/config/env.ts` for nothing. If a client var is ever genuinely needed, use the same Zod pattern against `import.meta.env`, and remember every `VITE_*` value is public by definition.
