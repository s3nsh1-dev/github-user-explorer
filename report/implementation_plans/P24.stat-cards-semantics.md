## Why

```tsx
// UserProfileStats.tsx:38-50
<Button variant="contained" sx={style2} disabled>
  <Typography>{userProfile.followers}</Typography>
  <Typography>Followers</Typography>
</Button>
```

Followers and Following are rendered as **disabled buttons** purely to match the
visual style of the clickable "Public Repos" card. Three consequences:

1. A disabled control is removed from the tab order and announced as
   "unavailable" — but this is data, not a broken control.
2. MUI's disabled styling greys the text, so the follower **count itself** may
   fail WCAG AA contrast — the number is the thing people came to read.
3. It implies these will become clickable, which is a promise the app does not
   keep. (`guide.txt` did plan "Following and Followers have pagination" — never
   built, and it is a feature, not a fix.)

## Steps

### 1. Replace the two disabled buttons with non-interactive cards

```tsx
const StatCard = ({ value, label }: { value: number; label: string }) => (
  <Paper elevation={1} sx={statCardStyle}>
    <Typography fontWeight={600}>{value}</Typography>
    <Typography variant="body2" color="text.secondary">{label}</Typography>
  </Paper>
);
```

Keep "Public Repos" as an interactive control — it genuinely navigates. After
**P23** it is a `RouterLink`.

### 2. Match the visuals deliberately

This is the actual work: the three cards currently look uniform *because* they
are all `Button`s. Getting `Paper` to match means re-matching width (90px),
height (90px), padding, border-radius, and elevation. Then make the difference
legible — the clickable one should look clickable (hover state, cursor) and the
other two should not.

That is a small design decision I am making autonomously: **interactive
affordance only on the interactive card.** If it looks wrong, it is reversible
in one commit.

### 3. Check contrast on the numbers

Once the disabled greying is gone, the counts render at full `text.primary`
contrast. Verify against both theme backgrounds (`#e0e0e0` / `#23272b`).

## Acceptance criteria

- [ ] Tab order: only "Public Repos" is focusable among the three
- [ ] Screen reader announces the follower/following counts as text, not as unavailable buttons
- [ ] Counts pass 4.5:1 contrast in both themes
- [ ] Layout unchanged — three equal cards, same spacing, no reflow
- [ ] "Public Repos" still navigates to `?tab=repositories`
- [ ] Verification gate green

## Do NOT

- Do not make followers/following clickable. That requires a followers list page with its own pagination — a feature (`guide.txt` wanted it), not a fix, and it needs its own API calls against a rate-limited endpoint.
- Do not remove the counts. They are useful data.
- Do not redesign the profile header layout. Scope is these two elements.
