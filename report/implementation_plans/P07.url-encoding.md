## Why

`/user/x%2F..%2F..%2Forgs%2Fgithub` decodes to `x/../../orgs/github`, the URL
parser normalises the `..` segments, and the request lands on
`api.github.com/orgs/github` **with the `Authorization` header attached**. Six
hooks build URLs by raw interpolation; none call `encodeURIComponent`.

It also breaks ordinary use: searching `C++` or anything containing `#` or `%`
produces a wrong or truncated query.

## Steps

### 1. Reproduce first

Load `/user/x%2F..%2F..%2Forgs%2Fgithub`, watch the Network tab, confirm the
request goes to `/orgs/github`. Without this I cannot prove the fix.

### 2. Build every URL with `URL` + `URLSearchParams`, never templates

```ts
const usersUrl = (login: string) =>
  new URL(`https://api.github.com/users/${encodeURIComponent(login)}`);

const reposUrl = (login: string, page: number, perPage = 8) => {
  const url = new URL(`https://api.github.com/users/${encodeURIComponent(login)}/repos`);
  url.searchParams.set("per_page", String(perPage));
  url.searchParams.set("page", String(page));
  return url;
};

const searchUrl = (q: string, page: number, perPage = 20) => {
  const url = new URL("https://api.github.com/search/users");
  url.searchParams.set("q", q);          // URLSearchParams encodes; do NOT pre-encode
  url.searchParams.set("page", String(page));
  url.searchParams.set("per_page", String(perPage));
  return url;
};
```

Put these next to `githubFetch` (`client/src/helper/githubUrls.ts`).
`encodeURIComponent` turns `/` into `%2F`, which GitHub treats as a literal
inside one path segment — the traversal collapses.

⚠️ **Do not double-encode.** `URLSearchParams.set` already encodes; passing
`encodeURIComponent(q)` to it yields `%2520`. Path segments need explicit
`encodeURIComponent`; query params must not have it.

### 3. Migrate the 6 hooks

`useFetchUserData`, `useFetchRepositories`, `useFetchReposPerPage`,
`useShowIndividualRepo`, and `useInfiniteUsers`.

*(`useFetchSearchUsers` was deleted in **P02** — if it is still present, P02 was
incomplete. Do not fix it; delete it.)*

### 4. Guard `page` parsing

`parseInt(searchParams.get("page") || "1", 10)` yields `NaN` for `?page=abc`
in [`Repositories.tsx:9`](../../client/src/page/Repositories.tsx#L9) and
[`DisplayRepoList.tsx:17`](../../client/src/components/DisplayRepoList.tsx#L17):

```ts
const parsePage = (raw: string | null): number => {
  const n = Number.parseInt(raw ?? "1", 10);
  return Number.isFinite(n) && n >= 1 ? n : 1;
};
```

### 5. Fix the `full_name` path construction

[`UserProfileRepos.tsx:47`](../../client/src/components/UserProfileRepos.tsx#L47)
navigates to `/user/${repo.full_name}`, relying on `full_name` containing a `/`
that the router splits into two params. Make it explicit:
`navigate(\`/user/${encodeURIComponent(owner)}/${encodeURIComponent(name)}\`)`.
`Repo` may need `owner` added to its type — or split `full_name` locally.

### 6. Encode before `navigate()` in the search form

[`LowerHomeUI.tsx:33`](../../client/src/components/LowerHomeUI.tsx#L33):

```tsx
navigate({ pathname: "/explore", search: `?${createSearchParams({ query: trimmed })}` });
```

## Acceptance criteria

- [ ] The traversal PoC now requests `/users/x%2F..%2F..%2Forgs%2Fgithub` (a literal 404), **not** `/orgs/github`
- [ ] `/explore?query=a%26per_page=100` sends `q=a%26per_page%3D100` as one param
- [ ] Searching `C++` returns sensible results
- [ ] `?page=abc` falls back to page 1, no `NaN` in any request URL
- [ ] `grep -rn 'api.github.com/\${\|api.github.com/.*\${' client/src` → no raw interpolation left
- [ ] Verification gate green

## Do NOT

- Do not apply `isValidLogin` as a hard gate here — that is **P16**, together with the real 404 page. Encoding alone must not change what renders.
- Do not validate or restrict the *search query*. GitHub qualifiers (`location:india`, `followers:>100`) must keep working; encoding preserves them, validation would not.
- Do not touch the GraphQL hooks — **P08**.
