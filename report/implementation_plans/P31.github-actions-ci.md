## Why

No `.github/` directory exists. Twelve PRs have been merged with nothing
verifying that the build even succeeds. A CI badge is also the single most
visible quality signal on a portfolio README.

Runs after **P29** and **P30** so the workflow is green on its first run — a CI
setup commit that lands red is worse than no CI.

## Steps

### 1. `.github/workflows/ci.yml`

```yaml
name: CI

on:
  push:
    branches: [main, rework/2026]
  pull_request:

jobs:
  verify:
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: client
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
          cache-dependency-path: client/package-lock.json

      - run: npm ci
      - run: npm run lint
      - run: npx tsc -b --noEmit
      - run: npm run test:run
      - run: npm run build

      - name: Audit (advisory)
        run: npm audit --audit-level=high
        continue-on-error: true
```

Notes on the non-obvious choices:

- **`npx tsc -b --noEmit` as its own step** even though `npm run build` already
  runs `tsc -b`. A type error then shows as a distinct failed step instead of
  being buried in build output.
- **Node 22, not 24.** Local is v24.18.1, but `react-router@7.6.2` declares
  `engines: node >= 20` and 22 is the current LTS — CI should test a version
  users will actually run. If the build fails on 22, that is worth knowing.
- **`continue-on-error` on `npm audit`.** It will likely flag unfixable
  transitive dev advisories. A permanently red X trains me to ignore CI.
- **`working-directory: client`** — this assumes the current layout. The
  npm-workspaces conversion is out of scope; if it ever happens, these paths
  change. Netlify builds with `base = "client"`, which matches this.

### 2. Do not add a deploy job

Netlify already builds and deploys on push — a second deploy path would race it,
and it would need the `GITHUB_TOKEN` secret. CI verifies; it does not ship.

## Acceptance criteria

- [ ] Workflow file is valid YAML (`npx yaml-lint` or push and observe)
- [ ] First run on the branch is **green**
- [ ] Deliberately break a test locally, push → CI fails at the test step. Fix, push, green. (Prove it actually runs.)
- [ ] Cache hit on the second run (visible in setup-node output)
- [ ] Total runtime under ~3 minutes

## Do NOT

- Do not add a deploy job or any secrets. Netlify owns deployment.
- Do not add branch protection rules — that is a repo setting only you can change, and it would block your own pushes.
- Do not add Lighthouse CI yet. Now that the URL is known (<https://github-userexplorer.netlify.app/>) it is viable, but it adds several minutes per run — revisit after **P26**/**P27** land, when the score is worth quoting.
- Do not run the matrix across multiple Node versions. One version, fast feedback, at this project size.
