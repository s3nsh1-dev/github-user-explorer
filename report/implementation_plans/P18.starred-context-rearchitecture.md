## Why — three bugs currently cancelling each other out

**Read this before touching anything.** The current code works by coincidence,
and any *individually correct* fix breaks it:

1. `initialList` is a plain `const` recomputed on **every render** — a
   synchronous `localStorage` read + `JSON.parse` per render (wasteful).
2. `checkStared` and `updateStaredList` read `initialList` (storage) instead of
   `staredList` (state).
3. The `localStorage` write happens **inside the state updater**, which React
   requires to be pure and calls twice under `StrictMode`.

Because (1) re-reads storage every render and (3) writes synchronously,
(2) accidentally stays in sync.

**Fix (1) alone — swap to a lazy `useState` initialiser — and `initialList`
freezes at its mount value, so the star icon stops toggling.** They must be
fixed together, in one commit.

Plus: the provider is mounted **twice independently**
([`UpperHomeUI.tsx:17`](../../client/src/components/UpperHomeUI.tsx#L17) and
[`ProfileInfo.tsx:120`](../../client/src/page/ProfileInfo.tsx#L120)), so
`localStorage` — not context — is doing the actual state sharing.

## Steps

### 1. Rewrite the provider

```tsx
const StarredUsersProvider = ({ children }: { children: ReactNode }) => {
  const [starredList, setStarredList] = useState<string[]>(readStarred);   // lazy: called once

  useEffect(() => { writeStarred(starredList); }, [starredList]);          // effect, not updater

  const checkStarred = useCallback(
    (login: string) => starredList.includes(login),                        // state, not storage
    [starredList]
  );

  const toggleStarred = useCallback((login: string) => {
    setStarredList((prev) =>
      prev.includes(login) ? prev.filter((v) => v !== login) : [...prev, login]
    );                                                                      // pure updater
  }, []);

  const value = useMemo(
    () => ({ starredList, checkStarred, toggleStarred }),
    [starredList, checkStarred, toggleStarred]
  );

  return <StarredUsersContext.Provider value={value}>{children}</StarredUsersContext.Provider>;
};
```

The `useMemo` on `value` matters — without it every provider render hands down a
new object and re-renders all consumers.

### 2. Hoist to the root, mount once

In [`main.tsx`](../../client/src/main.tsx), alongside `ModeContextProvider`.
Then **delete both nested wrappers**. `UpperHomeUI` becomes a plain layout box;
`ProfileInfo` loses a nesting level.

⚠️ This is why hoisting is required in the same commit as the effect-based
write: with two live provider instances and an effect that writes on every state
change, they would overwrite each other's list.

### 3. Make the hook throw instead of returning `null`

[`useStaredUserList.ts:6-9`](../../client/src/hooks/useStaredUserList.ts#L6)
returns `null` when the context is missing, which forces optional chaining at
every call site (`staredContext?.updateStaredList(...)`) and turns a wiring
mistake into a **silently dead star button**. Match `useMode`, which throws.
Once the provider is at the root the null case cannot legitimately occur.

Then drop the `?.` in
[`UserProfileHeader.tsx:51-54`](../../client/src/components/UserProfileHeader.tsx#L51).

### 4. Fix the stale `selectValue` in `StaredRepositories`

[Line 15](../../client/src/components/StaredRepositories.tsx#L15) stores the
last-clicked user in local state, so the dropdown label shows it forever, even
after navigating elsewhere. Derive from `useParams()`, or drop it and always
show the chevron. Prefer dropping it — simpler and always correct.

## ⚠️ Behaviour change

Storage is now read **once at app start** instead of on each page mount. If a
second tab stars a profile, this tab no longer picks it up on navigation. That
is a real (minor) regression in cross-tab behaviour, accepted deliberately —
note it in the commit message.
