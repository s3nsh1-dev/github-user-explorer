## Why

Two real bugs, one of them user-visible today:

1. **`useShowIndividualRepo` keys on `[repoName, "keyIsUnique"]` — no username.**
   Visit `/user/facebook/react`, then `/user/typescript-cheatsheets/react`
   within the 5-min `staleTime`, and you are shown Facebook's repo. Reproduce
   this before fixing, so I know the fix worked.
2. **`useFetchOrganizationRepos` and `useFetchContributionInfo` share
   `["contributionInfo", username]`** with different response shapes. Latent
   only because a login is never both a User and an Org.

## Steps

### 1. Create `client/src/constants/queryKeys.ts`

```ts
export const qk = {
  userProfile:   (login: string) => ["userProfile", login] as const,
  userRepos:     (login: string, page: number) => ["userRepos", login, page] as const,
  repo:          (owner: string, name: string) => ["repo", owner, name] as const,
  searchUsers:   (q: string) => ["searchUsers", q] as const,
  ownerType:     (login: string) => ["ownerType", login] as const,
  contributions: (login: string) => ["contributions", login] as const,
  orgRepos:      (login: string) => ["orgRepos", login] as const,
} as const;
```

`as const` matters — it gives TanStack Query v5 literal key inference.

### 2. Replace every `queryKey` with a `qk.*` call

| Hook | Was | Becomes |
|---|---|---|
| `useShowIndividualRepo` | `[repoName, "keyIsUnique"]` **← bug** | `qk.repo(username, repoName)` |
| `useFetchOrganizationRepos` | `["contributionInfo", username]` **← bug** | `qk.orgRepos(username)` |
| `useFetchContributionInfo` | `["contributionInfo", username]` | `qk.contributions(username)` |
| `useFetchLoginType` | `[username, "loginType"]` | `qk.ownerType(username)` |
| `useFetchUserData` | `["userProfile", username]` | `qk.userProfile(username)` |
| `useFetchRepositories` | `["public_repos", username]` | `qk.userProfile(username)` ⚠️ see below |
| `useFetchReposPerPage` | `["userRepos", username, page]` | `qk.userRepos(username, page)` |
| `useInfiniteUsers` | `["users", query]` | `qk.searchUsers(query)` |
| ~~`useFetchSearchUsers`~~ | — | **deleted in P02** (B4 answered) |

⚠️ **`useFetchRepositories` deliberately gets the same key as
`useFetchUserData`** — they fetch the identical URL. This is the setup for
**P10**, which deletes the hook entirely. Making the keys identical here means
React Query dedupes them immediately, and P10 becomes a safe deletion rather
than a behaviour change. Verify the key is byte-identical in both call sites.
