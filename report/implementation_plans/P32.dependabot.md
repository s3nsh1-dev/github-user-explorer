## Why

`client/package-lock.json` is ~4,000 lines of transitive dependencies with
nothing watching them. No Dependabot config, no automated auditing.

Given that [vulnerabilities/04](../vulnerabilities/04.missing-security-headers.md)
notes there is no CSP either, a compromised transitive dependency would have
free rein on the origin — so dependency freshness carries more weight here than
it normally would for a small SPA.

## Steps

### 1. `.github/dependabot.yml`

```yaml
version: 2
updates:
  - package-ecosystem: npm
    directory: /client
    schedule:
      interval: monthly
    open-pull-requests-limit: 5
    groups:
      dev-dependencies:
        dependency-type: development
      mui:
        patterns: ["@mui/*", "@emotion/*"]
    commit-message:
      prefix: "chore(deps)"

  - package-ecosystem: github-actions
    directory: /
    schedule:
      interval: monthly
```

Choices worth noting:

- **`monthly`, not `weekly`.** This is a portfolio repo; a reviewer reads the
  commit history. Weekly bump PRs bury your actual work under dependency noise.
- **Grouping** collapses the MUI/Emotion family (which release together) and all
  dev dependencies into single PRs instead of a dozen.
- **`directory: /client`** — the real dependency tree. The root
  `package.json` is `{"dependencies": {}}` with a lockfile that disagrees with
  it; auditing the root would scan a phantom tree. That cleanup is blocked on
  **B3**.
- **`github-actions` ecosystem** keeps the `actions/checkout@v4` pins in **P31**
  current.

## Do NOT

- Do not set `interval: daily`. It will generate more PRs than you have commits.
- Do not enable auto-merge. An auto-merged major bump on an unwatched portfolio repo silently breaks the deploy.
- Do not add a `/` npm entry until the root `package.json`/lockfile mismatch is resolved (**B3**).
- Do not run `npm audit fix --force`. It bumps majors and is out of scope for every plan here.
