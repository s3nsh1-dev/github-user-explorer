## Why

```tsx
// UserContributions.tsx:60-76
<Box sx={{ backgroundColor: day.color, width: "20px", height: "20px", fontSize: "0.7rem", color: "#fffff0" }}>
  {day.contributionCount}
</Box>
```

365 bare `<div>`s with no date, no label, no table semantics — the app's most
distinctive feature is completely invisible to assistive tech.

And the contrast is broken **for everyone**: the count renders in `#fffff0`
(near-white) on GitHub's contribution scale, whose lightest value is `#ebedf0`
(near-white). Zero-contribution days show white-on-white. The number is
unreadable on roughly the lightest third of the scale.

## Steps

### 1. Grid semantics

```tsx
<Box role="grid" aria-label={`${totalContributions} contributions in the last year`}>
  {weeks.map((week, i) => (
    <Box role="row" key={i}>
      {days.map((day, j) => (
        <Box
          key={j}
          role="gridcell"
          aria-label={day.date ? `${day.contributionCount ?? 0} contributions on ${day.date}` : "No data"}
          title={day.date ? `${day.contributionCount ?? 0} contributions on ${day.date}` : undefined}
          sx={{ backgroundColor: day.color, width: 20, height: 20, borderRadius: "10px" }}
        />
      ))}
    </Box>
  ))}
</Box>
```

### 2. ⚠️ Drop the visible number, use the tooltip

**This changes how the feature looks** — it is the one deliberate visual change
in the accessibility batch. Rationale:

- It fixes the contrast problem completely rather than patching it (no text colour works across the whole green scale).
- It is what GitHub itself does, so it reads as intentional rather than as a limitation.
- The padding-free 20px cell was never big enough for a 3-digit count anyway.

If keeping the digits matters more, the alternative is computing a per-cell
contrast-aware text colour from `day.color` — doable, but more code for a worse
result. Going with the tooltip.

### 3. Provide a text alternative for the whole grid

A `role="grid"` of 365 cells is exhausting to navigate linearly. Add a visually
hidden summary before it: total contributions, date range, best day. Screen
reader users get the substance in one sentence.

## Acceptance criteria

- [ ] Hovering any cell shows date + count
- [ ] Screen reader: grid is announced with a summary; individual cells give date + count
- [ ] No white-on-near-white text anywhere in the grid
- [ ] The grid still looks like the GitHub contribution graph (that is the point of the feature)
- [ ] Empty padding cells (`date: ""`) are not announced as real days
- [ ] axe DevTools: no contrast violations on the profile page
- [ ] Verification gate green

## Do NOT

- Do not change the cell colours. They come from GitHub's API (`day.color`) and matching GitHub is the feature.
- Do not add a charting library. It is a CSS grid of divs; that is correct and dependency-free.
- Do not make cells focusable individually — 365 tab stops is hostile. `role="gridcell"` gives screen reader navigation without adding tab stops.
- Do not touch the org top-repos view. Different component, no issues found.
