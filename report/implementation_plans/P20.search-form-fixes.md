## Why

```tsx
// client/src/components/LowerHomeUI.tsx:27-33
const trimUserName = searchTerm.trim();
if (searchTerm.length <= 2) {              // ← validates the UNTRIMMED value
  alert("Please enter at least 3 characters to search for a user.");
  return;
}
navigate(`/explore?query=${trimUserName}`);  // ← navigates with the TRIMMED value
```

Two problems: a native `alert()` (blocks the main thread, unstyleable, looks
broken on mobile — the clearest "student project" tell in the codebase), and a
real validation bug — typing `"  a  "` is length 5, passes the guard, and
navigates to `?query=a`, the single-character search the guard exists to prevent.

## Steps

### 1. Validate the trimmed value, show the error inline

```tsx
const [error, setError] = useState<string | null>(null);

const handleSearch = (event: FormEvent) => {
  event.preventDefault();
  const trimmed = searchTerm.trim();
  if (trimmed.length < 3) {
    setError("Enter at least 3 characters.");
    return;
  }
  setError(null);
  navigate({ pathname: "/explore", search: `?${createSearchParams({ query: trimmed })}` });
};
```

```tsx
<TextField
  value={searchTerm}
  onChange={(e) => { setSearchTerm(e.target.value); setError(null); }}
  error={Boolean(error)}
  helperText={error ?? " "}        // ← non-breaking space reserves the row; prevents layout jump
  label="GitHub username"
  id="github-username-search"
  autoFocus
/>
```

`helperText={error ?? " "}` is deliberate — an empty string collapses the
element and the form jumps when an error appears.

### 2. Replace the manual focus effect with `autoFocus`

[Lines 19-23](../../client/src/components/LowerHomeUI.tsx#L19) use a `useRef` +
`useEffect` to focus on mount. The native prop does the same thing; drop the ref
and the effect.

### 3. `label` instead of `placeholder`

A placeholder is not a label — it disappears on focus and typically fails
contrast. MUI wires `label` to a real `<label for>`. This is also
[suggestions/09](../suggestions/09.accessibility.md) §9d, closed here.

### 4. Rename the copy-pasted id

`id="outlined-basic"` is straight from the MUI docs.

### 5. Do NOT `encodeURIComponent` the query yourself

`createSearchParams` already encodes. Pre-encoding yields `%2520`. (Same trap as
**P07** §2.)

## Do NOT

- **Do not add debounced search suggestions.** Ruled out in **P37** — debouncing an on-submit search does nothing, and live suggestions would hammer GitHub's tightest endpoint. Submit-only is the better design.
- **Do not add the navbar search box here.** **P37** does it, and it extracts this form into a shared `<SearchBar>`. Fix the logic here; move it there.
- Do not touch `useFetchSearchUsers` — already deleted in **P02**.
- Do not add search history / recent searches. Another feature, another `localStorage` key, out of scope.
