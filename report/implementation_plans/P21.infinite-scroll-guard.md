## Why

```tsx
// client/src/page/Explorer.tsx:45-67
useEffect(() => {
  if (!hasNextPage || isFetchingNextPage) return;      // ← guards effect registration
  const observer = new IntersectionObserver((entries) => {
    if (entries[0].isIntersecting) fetchNextPage();    // ← callback has no guard
  }, { root: null, rootMargin: "0px", threshold: 1.0 });
  ...
```

The guard runs when the **effect re-registers**, not per callback invocation.
A user holding `End`, or a scripted scroll loop, walks pages as fast as the
network allows — against GitHub's **tightest** limit (10 searches/min
unauthenticated, 30 authenticated). Thirty requests is about 30 seconds of
enthusiastic scrolling.

There is a second, subtler bug: **`threshold: 1.0` requires the sentinel to be
100% visible.** The sentinel is a 40px `Box` inside a flex column — on a short
viewport, or if the sentinel is ever taller than the visible area, it can never
be fully visible and **pagination silently stops working**.

## Steps

### 1. Guard inside the callback, and loosen the threshold

```tsx
useEffect(() => {
  const el = loadRef.current;
  if (!el) return;

  const observer = new IntersectionObserver(
    ([entry]) => {
      if (entry.isIntersecting && hasNextPage && !isFetchingNextPage) {
        fetchNextPage();
      }
    },
    { root: null, rootMargin: "200px", threshold: 0 }   // prefetch before the user hits bottom
  );

  observer.observe(el);
  return () => observer.disconnect();
}, [hasNextPage, isFetchingNextPage, fetchNextPage]);
```

Three changes: guard moved into the callback, `threshold: 0` (fires as soon as
any pixel is visible), `rootMargin: "200px"` (starts loading 200px early, so
scrolling feels seamless).

`observer.disconnect()` in cleanup rather than `unobserve` — simpler and
unconditionally correct.

### 2. Verify the sentinel is always mounted when `hasNextPage`

The sentinel currently sits inside `{hasNextPage && (...)}`. That is fine — but
after **P02** deleted the dead nested block, re-check that `loadRef` still
attaches. If the ref is conditionally rendered, the `if (!el) return` above
handles it; the effect re-runs when `hasNextPage` flips.

### 3. Confirm P11's retry policy is active

A rate-limit 403 must not retry. If **P11** landed, `RateLimitError` returns
`false` from the retry predicate. Verify rather than assume — this is the code
path where it matters most.

## Acceptance criteria

- [ ] Scroll a large result set (`?query=a`) → pages load smoothly, one request per page
- [ ] Hold `End` for 10 seconds → requests are bounded by in-flight state, not by scroll events (watch the Network tab; there should be no burst)
- [ ] Short viewport (resize to ~400px tall) → pagination still triggers (this is the `threshold: 1.0` bug)
- [ ] Reaching the end shows the end-of-results message exactly **once**
- [ ] Hitting the rate limit → `<ErrorState>` with reset time, and **no retry storm**
- [ ] Verification gate green

## Do NOT

- Do not add a manual "Load More" button back. **P02** deleted the commented-out one; the observer is the intended design.
- Do not add throttle/debounce libraries. The in-flight guard is the correct mechanism — `isFetchingNextPage` already exists.
- Do not change `per_page: 20`. Behaviour change without a reason.
