## Why

```tsx
// PageQuickButtons.tsx:11-20
const handleClick = () => navigate(link);
return <IconButton onClick={handleClick} disabled={disabled}>{icon}</IconButton>;
```

Pagination navigates to real URLs (`/user/:login?tab=repositories&page=N`), but
renders as `<button>`. That loses middle-click, ⌘-click "open in new tab", the
hover URL preview, and the `link` role. Same in
[`PageButton.tsx:43-45`](../../client/src/components/PageButton.tsx#L43) and
[`UserProfileStats.tsx:26-28`](../../client/src/components/UserProfileStats.tsx#L26).

For a browsing app where users compare profiles, "open in a new tab" is a real
loss, not a theoretical one.

## Steps

### 1. Render as `RouterLink`

```tsx
import { Link as RouterLink } from "react-router-dom";

<IconButton component={RouterLink} to={link} aria-label={label}>
  {icon}
</IconButton>
```

### 2. ⚠️ Handle `disabled` — anchors cannot be disabled

This is the one real complication. An `<a>` has no `disabled` attribute, and
`pointer-events: none` alone leaves it keyboard-focusable and clickable via
Enter. Two acceptable options:

**Option A (preferred) — render a plain disabled button when disabled:**

```tsx
if (disabled) return <IconButton disabled aria-label={label}>{icon}</IconButton>;
return <IconButton component={RouterLink} to={link} aria-label={label}>{icon}</IconButton>;
```

Simple, semantically honest, and `disabled` still removes it from the tab order.

**Option B — omit the control entirely** when it would be disabled. Cleaner
visually but the pagination bar changes width as you page, which is worse.

Go with A.

### 3. Apply to all three components

- `PageQuickButtons.tsx` — the four arrows
- `PageButton.tsx` — numbered pages (keep `aria-current` from **P22**)
- `UserProfileStats.tsx:26-28` — the "Public Repos" card, which navigates

`PageQuickButtons` no longer needs `useNavigate` at all — delete the import.

## Acceptance criteria

- [ ] ⌘-click / middle-click a page control → opens in a new tab with the right URL
- [ ] Hovering shows the destination URL in the status bar
- [ ] Disabled first/prev on page 1 and next/last on the final page — not focusable, not clickable
- [ ] Keyboard: Enter activates; disabled controls are skipped in the tab order
- [ ] Active page still marked with `aria-current="page"`
- [ ] Verification gate green

## Do NOT

- Do not use `component="a"` with a raw `href` — that triggers a full page reload and throws away the SPA. It must be `RouterLink`.
- Do not use `pointer-events: none` as the disabled mechanism. It leaves the control keyboard-reachable — a worse bug than the one being fixed.
- Do not restyle the diamond `clipPath`. Visual redesign is out of scope; the focus-ring fix already landed in **P22**.
