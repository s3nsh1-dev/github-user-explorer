## Why

`new QueryClient()` ([`main.tsx:9`](../../client/src/main.tsx#L9)) uses the
library default of **3 retries with exponential backoff**. On a 403 rate-limit
response that turns one request into four and drives you further past the
limit — a self-reinforcing failure.

Also: `useFetchReposPerPage` has its `staleTime` **commented out**
([line 34](../../client/src/hooks/useFetchReposPerPage.ts#L34)), so the
repositories list refetches on every pagination click while its six siblings
cache for 5 minutes. That is the screen visitors click through fastest.

`guide.txt` lists *"Handle auth and errors globally using React Query's
QueryClient config"* as planned and never done. This is it.

## Steps

### 1. Configure defaults in `main.tsx`

```ts
import { RateLimitError, NotFoundError } from "./helper/githubErrors";

const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 5 * 60_000,
      gcTime: 30 * 60_000,
      refetchOnWindowFocus: false,
      retry: (failureCount, error) => {
        if (error instanceof RateLimitError) return false;  // retrying makes it worse
        if (error instanceof NotFoundError) return false;   // 404 will not become 200
        return failureCount < 1;
      },
    },
  },
});
```

`gcTime` is the v5 name for what v4 called `cacheTime` — the commented-out block
**P02** deleted was referring to the old API.

### 2. Remove now-redundant per-hook `staleTime: 1000 * 60 * 5`

Six hooks repeat it. The default covers them. Delete the local overrides so
there is one place to tune.

### 3. Uncomment / restore `staleTime` behaviour for `useFetchReposPerPage`

It now inherits the 5-minute default — no local option needed. Add
`placeholderData: keepPreviousData` so paging does not flash a spinner between
pages:

```ts
import { keepPreviousData } from "@tanstack/react-query";
// ...
placeholderData: keepPreviousData,
```

- Do not raise `retry` above 1. The point of this plan is fewer requests, not more.
