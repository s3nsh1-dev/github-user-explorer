## Why — measured

```
github-logo.png              2.0 MB   unused
website_logo_1_original.png  2.0 MB   unused
website_logo_3_original.png  2.0 MB   unused
github-logo-cropped.png      1.4 MB   ← the FAVICON
website_logo_3.png           536 KB   navbar (dark), displayed at 120×50
website_logo_1.png           496 KB   navbar (light), displayed at 120×50
```

A **1.4 MB favicon**, declared `type="image/svg+xml"` while being a PNG. And
~500 KB logos rendered at 120×50 CSS pixels — about **60× more bytes than the
display needs**, both loaded regardless of theme because both are statically
imported.

No ImageMagick/cwebp in this environment, but **Python PIL 12.1.1 is available**.

## Steps

### 1. Generate the favicon set with PIL

```python
from PIL import Image
src = Image.open("client/src/assets/github-logo-cropped.png").convert("RGBA")
for size, name in [(32, "favicon-32.png"), (16, "favicon-16.png"), (180, "apple-touch-icon.png")]:
    src.resize((size, size), Image.LANCZOS).save(f"client/public/{name}", optimize=True)
```

Expect ~2 KB for the 32px, ~10 KB for the 180px. From 1.4 MB.

Then fix [`client/index.html:5-9`](../../client/index.html#L5) — note the
**wrong MIME type** is being corrected here too:

```html
<link rel="icon" type="image/png" sizes="32x32" href="/favicon-32.png" />
<link rel="icon" type="image/png" sizes="16x16" href="/favicon-16.png" />
<link rel="apple-touch-icon" sizes="180x180" href="/apple-touch-icon.png" />
```

Referencing from `/` (i.e. `client/public/`) rather than `./src/assets/…` is
correct — `public/` is copied verbatim, which is where a favicon belongs.

### 2. Resize the navbar logos

Display size is 120×50; target 2× DPI → 240×100. Preserve aspect ratio, do not
distort:

```python
for n in ("website_logo_1", "website_logo_3"):
    img = Image.open(f"client/src/assets/{n}.png").convert("RGBA")
    img.thumbnail((240, 100), Image.LANCZOS)          # preserves aspect ratio
    img.save(f"client/src/assets/{n}.png", optimize=True)
```

Expect ~15 KB each, from ~500 KB. **Check the result visually** — these are the
site's branding and a bad resample is worse than a large file.

Optionally also emit `.webp` and use `<picture>`. Skip unless the PNG is still
large; the complexity is not worth ~5 KB.

### 3. ⚠️ RELOCATE the masters — do not delete

`git mv` (never `rm`) the three unused large PNGs to `docs/assets-source/`:

