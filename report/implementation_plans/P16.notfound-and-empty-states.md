## Why

`NotFound` is `<div>Not Found</div>` — three words, unstyled, in an app with a
custom dark theme. And five call sites feed the literal string `"demoUserName"`
to the GitHub API as a real username whenever a route param is missing.

There is even an unused design mockup for this screen at
[`extra/userNotFound-design.png`](../../extra/userNotFound-design.png).

## Steps

### 1. Rebuild `NotFound.tsx` as a themed, parameterised page

```tsx
type Props = { title?: string; message?: string };

const NotFound = ({ title = "404", message = "That page doesn't exist." }: Props) => (
  <Box sx={{ minHeight: "70vh", display: "grid", placeItems: "center", textAlign: "center", gap: 2, p: 3 }}>
    <Typography fontFamily="monospace" fontSize={{ xs: 48, sm: 64 }}>{title}</Typography>
    <Typography color="text.secondary">{message}</Typography>
    <Button component={RouterLink} to="/" variant="contained">Back to search</Button>
  </Box>
);
```

Parameterising lets one component serve "user not found", "repository not
found", and "page not found".

### 2. `client/src/components/EmptyState.tsx`

Generic themed empty state: icon, title, body, optional action. Used by 3-6
below.

### 3. Replace all five `"demoUserName"` fallbacks with real guards

| File | Line |
|---|---|
| `ProfileInfo.tsx` | 46, 127 |
| `Repositories.tsx` | 10, 18 |
| `DisplayRepoList.tsx` | 19 |
| `ShowSelectedRepo.tsx` | 30-31 (also `"demoRepo"`) |

```tsx
const { username } = useParams();
if (!isValidLogin(username)) return <NotFound title="Invalid username" message="That doesn't look like a GitHub username." />;
```

`isValidLogin` from **P04** is a type predicate, so `username` narrows to
`string` after this line and the fallbacks are genuinely unnecessary — no cast
needed. Same for `isValidRepoName` in `ShowSelectedRepo`.

**This is also the defence-in-depth half of V02/V03** — invalid input never
reaches a request at all.

### 4. `Explorer` with no query

[`Explorer.tsx:41`](../../client/src/page/Explorer.tsx#L41) currently searches
for the literal string `"noQueryToSearch"`. Replace with an empty state
prompting for a search.

### 5. Zero-result search

`total_count === 0` currently renders "Matching Results : 0" **and** the
celebratory *"🎉 You've reached the end of results!"*. Branch: no results →
`<EmptyState>` suggesting a spelling check. Keep 🎉 only for "you scrolled
through everything".

### 6. Remaining empty states

- User with 0 public repos — `UserProfileRepos.tsx:57` plain text → `<EmptyState>`
- **No starred profiles** — `StaredRepositories.tsx:71` opens an empty menu. This is the first interactive element on the home page; make it say "Star a profile to pin it here."

### 7. Move the catch-all route last

[`App.tsx:23`](../../client/src/App.tsx#L23) declares `path="*"` **before**
`/user/:username/:repoName`. React Router v6+ ranks by specificity, so this is
**not a bug** — but every reader has to stop and verify that. Move it last.

## Acceptance criteria

- [ ] `/user/-invalid-` → themed "Invalid username", no API request fired (check Network tab)
- [ ] `/explore` with no query → prompt, no API request
- [ ] A search with 0 results → helpful empty state, no 🎉
- [ ] `/nonexistent-route` → themed 404

## Do NOT

- Do not put a `<SearchBar>` on the 404 page yet. The shared component is part of the blocked navbar-search feature (**B5**); a "Back to search" button is enough and does not fork the design.
- Do not loosen `isValidLogin` if a real username gets rejected — investigate the regex against GitHub's actual rules first. If a genuine login fails, that is a **P04** bug, fix it there.
- Do not redesign from `extra/userNotFound-design.png` wholesale — that mockup is blocked material (**B8**) and may not match the current theme.
